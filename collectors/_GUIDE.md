# collectors/ — 폴더 가이드

## 역할

**맥에서 도는** 수집기들. 서버(`src/`, 데스크탑)와 따로 배포되고 따로 돈다.

| 수집기 | 하는 일 | 도는 방식 |
|--------|---------|-----------|
| `chrome_history` | 크롬 방문 기록을 읽어 `web_visit` 흔적을 보낼 상자에 적는다 | launchd, 한 시간마다 |
| `mac_apps` | 앞에 뜬 앱을 30초마다 보고 사용 구간을 보낼 상자에 적는다 | launchd, 계속 |
| `forward` | 폰(iCloud 파일)과 보낼 상자의 줄을 서버로 보낸다 | launchd, 5분마다 |

**이 폴더가 소유하지 않는 것**: 받은 것을 어떻게 접고 저장할지(→ `src/runtime/ingest.py`),
어떤 종류가 있는지(→ 각 섹터의 카드). 수집기는 **배달만** 한다.

## 핵심 패턴

### 맥 시스템 파이썬(3.9) + 표준 라이브러리만
```python
from collectors.common import post   # ✅
from src.core.models import Trace     # ❌ 서버 코드는 3.11 문법과 pydantic 을 쓴다
```
**이유**: launchd 는 로그인 셸을 거치지 않아 anaconda 가 안 보인다. `/usr/bin/python3`
로 돈다. 저장소 루트에서 `-m collectors.<이름>` 으로 실행한다.

### 어디까지 보냈는지 기억하고, 성공한 뒤에만 옮긴다
```
크롬     visits.id (몇 번째 줄까지)      상태 폴더/chrome_history.json
배달부   파일마다 바이트 위치 + 앞부분 지문   상태 폴더/forward.json
앱       지금 열린 구간                 상태 폴더/mac_apps.json
```
**이유**: 서버가 꺼져 있거나 연결이 끊긴 동안의 데이터를 잃지 않는다. 상태 폴더는
`~/Library/Application Support/jarvis/` 이다 — 저장소를 지워도 커서가 산다.
서버는 같은 것을 여러 번 받아도 안전하므로(멱등), 애매하면 다시 보낸다.

### 수집기는 개발하는 저장소가 아니라 사본에서 돈다
```
~/Library/Application Support/jarvis/app/   ← origin 기본 브랜치만 받는 사본. install.sh 가 만들고 갱신한다
```
**이유**: launchd 가 개발 저장소에서 돌리면 브랜치를 바꾸거나 고치는 도중에 정시 실행이 걸려,
반쯤 고친 코드가 커서를 옮긴다. 2026-10-30 설치 첫날 한 시간 넘게 그 상태로 돌았다(그동안
수집기 코드는 안 바뀌어서 탈은 없었다). 업데이트는 머지 뒤 `sh collectors/install.sh` 한 번.

### 단축어는 파일에 적고, 보내는 건 맥이 한다
```
아이폰 단축어 → iCloud Drive/단축어/jarvis/inbox.jsonl → forward → 서버
```
**이유**: 단축어가 직접 쏘면 그 순간 폰이 서버에 닿아야 하고, 실패한 데이터는 사라진다.
`forward.py` 머리말에 사고와 줄 모양이 있다.

## 금지사항

### ❌ 크롬 기록을 시각으로 이어 읽지 않는다
```python
# ❌ 금지 — "마지막으로 보낸 시각 이후" 를 읽는다
# ✅ 대신 — visits.id 커서. 늦게 들어온 줄도 새 번호를 받는다
```
**이유**: 아이폰에서 본 페이지는 동기화를 거쳐 맥 DB에 늦게 들어오는데 방문 시각은
원래 시각이다. 시각 커서는 그걸 영영 건너뛴다.
**사고 이력**: 2026-10-30 실측. 2주간 다른 기기 방문 1,953건 중 6시간 넘게 늦은 게 19건,
최대 12.8시간. 그 전 수집기는 "최근 3시간"을 읽어 이런 방문을 놓쳤다.

### ❌ 이미 보낸 방문을 다시 접어 보내지 않는다
```python
# ❌ 금지 — 새 방문이 닿은 칸을 그 칸의 모든 방문으로 다시 접는다
# ✅ 대신 — 커서 아래는 다 보낸 것, 커서 위에서 먼저 보낸 것은 번호(sent_above)로 기억
```
**이유**: 서버는 (시각, 텍스트)가 같아야 중복으로 본다. 다시 접으면 칸의 첫 방문이 바뀌거나
(더 이른 방문이 늦게 동기화됨) 페이지 제목이 바뀌어(안 읽은 메일 수) 키가 달라지고,
이미 보낸 방문이 새 줄로 또 들어간다.
**사고 이력**: 2026-10 이전 수집기는 겹쳐 읽을 때 접어 보낸 방문을 새 줄로 다시 넣었고,
방문 수를 엉뚱한 줄(바로 앞 줄)에 붙였다. 2026-10-30 첫 수정본(칸 전체 다시 접기)도
리뷰에서 위 두 경우로 같은 방문을 두 번 세는 게 재현됐다.
2차 리뷰에서 하나 더 나왔다: 직접 보낼 때는 덩어리 여럿 중 일부만 들어가고 끊기면 다음
실행이 들어간 방문을 다시 접어 드물게 두 번 셌다(재현: 실제 3, 저장 4). 그래서 크롬도
맥 앱처럼 **보낼 상자에 적고 배달부가 줄 단위로 보낸다**(2026-10-30). 끊긴 줄은 같은 줄
그대로 다시 가므로 서버가 하나로 본다.

### ❌ 크롬 커서를 확인 없이 믿지 않는다
```python
# ❌ 금지 — 저장된 after_id 위만 읽는다
# ✅ 대신 — 번호 최고 기록(sqlite_sequence)이 커서보다 작으면 처음부터 다시 읽는다
```
**이유**: 모든 기간 기록 삭제나 손상 복구 뒤에 크롬은 번호를 1부터 다시 붙인다. 커서를
그대로 두면 새 방문이 전부 커서 아래로 숨어 매시간 "흔적 0개"로 멈추는데, 조용한
시간과 구별되지 않는다. MAX(id) 로 재면 최근 기록만 지워도 다시 읽게 되므로 최고 기록을 본다.
**사고 이력**: 2026-10-30 리뷰에서 합성 DB 로 재현(세 번 연속 저장 0건).

### ❌ 3.10 이상에서만 같은 예외 이름에 기대지 않는다
```python
# ❌ 금지 — except (URLError, TimeoutError): ...   # 3.9 의 socket.timeout 이 빠져나간다
# ✅ 대신 — except OSError: ...                    # HTTPError 는 그 앞에서 따로 잡는다
```
**이유**: 수집기는 3.9 로 돌고 테스트는 3.10 이상으로 돈다. 3.9 에서 답 없는 서버의
`socket.timeout` 은 `TimeoutError` 가 아니다. `tests/unit/test_collectors_common.py` 가
맥에서 `/usr/bin/python3` 로 한 번 더 확인한다.
**사고 이력**: 2026-10-30 리뷰. 배달부가 그 예외를 "파일을 못 읽었다"로 적고 다음 파일로 넘어갔다.

## 모듈 지도

| 파일 | 책임 |
|------|------|
| `common.py` | 상태 폴더, 토큰, 보낼 상자 파일, 서버로 보내기. 실패를 `Retry`(나중에 다시)와 `Rejected`(내용이 틀림)로 나누고, 거절된 것은 `set_aside` 로 따로 둔다 |
| `chrome_history.py` | 크롬 기록 → `web_visit`. id 커서 + 먼저 보낸 번호, 시계 칸으로 접기, 안 닫힌 칸은 미룸, 기록 재생성 감지 |
| `mac_apps.py` | 앞 앱 표본 → 사용 구간 → 보낼 상자. 자리 비움·잠듦·정시에서 끊는다 |
| `forward.py` | iCloud 받은 편지함과 보낼 상자의 줄 → 서버. 깨진 줄·거절된 줄은 뒤를 막지 않게 따로 두고 `--replay` 로 되살린다. 폴더 하나를 못 열어도 나머지는 보낸다 |
| `install.sh` | 사본(app/)을 받아 최신으로 맞추고 launchd 에 셋을 올리고 내린다. 업데이트도 이것 |
| `launchd/` | plist 틀. 경로는 `install.sh` 가 채운다 |
