# src/core/ — 폴더 가이드

## 역할

전 레이어가 공유하는 도메인 모델과, 도메인 지식이 없는 계산.
`Observation`·`Insight`·`Metric` 같은 타입과 하루치로 접는 산수가 여기 산다.

**이 폴더가 소유하지 않는 것**: 특정 섹터의 지식. 애플이든 가민이든 알면 안 된다.
저장 방법(→ `storage`), 판단(→ `brain`), 수집(→ `runtime`)도 아니다.

---

## 핵심 패턴

### 출처를 인자로 받는다
```python
# ✅ 이렇게
def daily_sum(samples, kind: str, source: str) -> List[Observation]: ...
```
**이유**: `SOURCE = "apple_health"` 를 상수로 두면 플랫폼이 애플을 아는 것이다.
가민을 붙이는 날 이 파일을 열게 된다.

### frozen dataclass
```python
@dataclass(frozen=True)
class Observation: ...
```
**이유**: 파이프라인을 흘러가는 동안 누가 값을 바꾸지 못하게. 수집→감지→판단→발신을
지나면서 어디서 변조됐는지 추적하는 일은 피하고 싶다.

## 금지사항

### ❌ 섹터를 import 하지 않는다
```python
# ❌ 금지
from src.sectors.health import METRICS

# ✅ 대신 — 필요한 것을 인자로 받는다
def fold(samples, kind: str, source: str): ...
```
**사고 이력**: 2026-08-25 구조 개편 전, `parsers/health.py` 가 접는 계산과 애플 XML
파싱을 함께 갖고 있어서 둘을 떼어낼 수 없었다. 플랫폼이 도메인을 알면 섹터를 늘릴 때마다
플랫폼도 고쳐야 한다.

### ❌ 지표 이름을 상수로 박지 않는다
```python
# ❌ 금지
SLEEP_KIND = "sleep_hours"
```
**사고 이력**: 2026-08-24 `sleep_hours` 하나를 네 파일이 조금씩 알고 있었다. 휴식기
심박으로 갈아탈 때 접는 법은 등록했는데 수집 선언을 빠뜨려, 자비스가 일부러 버린 지표를
되살리라고 조를 뻔했다.

## 금지사항 (추가)

### ❌ 근거 없는 주제를 만들지 않는다
```python
# ❌ 금지 — 근거 없이, 또는 모델이 적은 글로 주제를 만든다
# ✅ 대신 — 이번 프롬프트에 보여준 흔적 번호 둘 이상(plan 의 offered, MIN_EVIDENCE)
```
**사고 이력**: 2026-08-26. 회고 실험에서 모델이 7일 평균 두 개를 비교해놓고
"상관관계가 뚜렷하게 나타난다"고 썼다. **근거를 실제보다 세게 말하는 게 이
방식의 주된 실패 모양이다.** 옛 믿음은 모델 자체(`Belief.__post_init__`)에서
막았지만 근거가 흔적 글이라 실제 흔적인지는 프롬프트에만 기댔다(10-08 시험에선 23개
모두 맞았다). 주제 나무(JAR-021)는 근거를 흔적 **번호**로 받고 보여준 번호가 아니면
검사(`plan`)가 뺀다 — 저장 직전이 아니라 연산을 받는 자리에서 막는다.

### ❌ 나무를 저장소에서 직접 고치지 않는다
```python
# ❌ 금지 — UPDATE topics SET parent_id = ...   (회고나 CLI 에서 바로)
# ✅ 대신 — Op → plan(나무 사본에서 검사) → SQLiteTopicStore.apply(한 트랜잭션, 변경 기록)
```
**이유**: 변경 기록(`topic_changes`)이 나무가 얼마나 자주 바뀌는지 재는 유일한 재료다(3단계 끝 기준).
기록을 건너뛴 변경이 하나라도 있으면 "왜 이 주제가 여기 있지"를 거슬러 올라갈 수 없다.
**사고 이력**: 2026-10-08 구조 재검토. 옛 믿음은 회고마다 `value` 를 통째로 덮어써서 옛 근거와 새
값이 섞였고, 무엇이 언제 바뀌었는지 남지 않았다.

### ❌ 주제의 근거를 살아 있는 가지만으로 세지 않는다
```python
# ❌ 금지 — tree.subtree(topic)   # 살아 있는 자손만
# ✅ 대신 — tree.lineage(topic)   # 접힌 가지까지. standings 와 stale 이 같이 쓴다
```
**사고 이력**: 2026-11-02 JAR-021 리뷰 재현. 가지를 만들면 근거가 줄기에서 가지로 내려간다(가장 구체적인
주제). 그 가지를 접거나 다른 줄기로 옮기자 줄기가 "뜨는 중 · 18개"에서 바로 "잠잠 · 0개"가 됐고, 다음
회고가 **하루 전에 근거가 있던 줄기**를 "60일 동안 근거가 없다"며 접었다. 근거가 하나도 안 남은 줄기는
만든 때가 아니라 "근거가 하나도 남지 않았다"로 접는다 — 변경 기록의 이유가 사실이어야 한다.

### ❌ 코드가 바꾼 것을 모델의 변경으로 세지 않는다
```python
# ❌ 금지 — 변경 기록의 op 만 보고 rename·move·merge·retire 를 센다
# ✅ 대신 — plan(..., actor=CODE) 로 기록하고 churn() 은 actor=model 만 센다
```
**사고 이력**: 2026-11-02 JAR-022 리뷰 재현. 모델은 첫날 하나 만들고 매일 "바꿀 것 없음"이었는데, 되감기
요약이 "모양 바꾼 날 1/66일"이었다 — 오래 잠잠해 코드가 접은 주제를 센 것이다. 이 숫자가 "구조 변경도 두 번
제안돼야 적용할지"(BACKLOG)의 근거라, 부풀면 쓸데없는 규칙이 생긴다.

### ❌ 같은 응답의 ref 보다 있는 주제 번호를 먼저 보지 않는다
**사고 이력**: 2026-11-02 JAR-021 리뷰 재현. 모델이 ref 를 "1" 로 지어 새 주제를 만들고 메모를 달았는데,
있는 #1 이 먼저 잡혀 메모가 **아무 표시 없이** 엉뚱한 주제(취업)로 갔다. 빠진 create 의 ref("3")를 가리킨
연산도 있는 #3 으로 샜다. ref 를 먼저 보고, 빠진 ref 를 가리키면 같이 뺀다(`_resolve`).

### ❌ 값이 없는 것을 관측치로 담지 않는다
```python
# ❌ 금지 — Observation(kind="location", value=0, meta={"lat": …, "lon": …, "trigger": …})
# ✅ 대신 — Event(kind="location", label="wallet", lat=…, lon=…)   # 사건 표
```
**이유**: 관측치는 숫자 하나다. 접히고(합계·평균), 추이로 비교되고, "최근 값"으로 LLM 에게
간다. 숫자가 아닌 것을 0 으로 채워 넣으면 그 모든 길에서 숫자로 취급된다.
**사고 이력**: 2026-08-25 ~ 10-02 위치 74건이 전부 값 0 으로 쌓였고, 자비스에게 보여주는 "최근
값"에 "위치 0 · 0 · 0" 이 들어갔다. 2026-11-02 사건 표로 옮겼다(`app/migrate.py`).

### ❌ 비밀값이 로그에 남게 두지 않는다
```python
# ❌ 금지 — 토큰이 든 URL 을 그대로 찍는 라이브러리 로그를 방치
# ✅ 대신 — 시작할 때 hide_in_logs(설정의 비밀값들). 기록은 남기고 값만 지운다
```
**사고 이력**: 2026-10-30. 텔레그램 API 는 봇 토큰을 URL 에 넣고, httpx 가 INFO 로 그
URL 을 통째로 찍었다. 듣기 루프가 30초마다 돌아 journalctl 에 토큰이 하루 2,880번 남았고,
그 로그가 디버깅 중 채팅에 그대로 붙여넣어졌다.

### ❌ 수면 조각을 하나씩 밤에 배정하지 않는다
```python
# ❌ 금지 — 조각마다 시작 시각으로 "어느 밤"을 정한다
# ✅ 대신 — 1시간 안에 이어진 조각을 잠 덩어리로 묶고, 덩어리째 밤에 배정한다
```
**이유**: 정오가 밤의 경계라, 정오를 넘겨 잔 날은 정오 뒤 조각이 "다음 밤"으로 떨어진다.
그 꼬리가 조각 셋을 넘으면 측정 품질 검사를 통과해, 수면 급감 트리거가 오래 잔 날
"어젯밤 수면 1.5시간"으로 URGENT 를 낸다.
**사고 이력**: 2026-10-30 JAR-013 리뷰에서 합성 데이터로 재현. 실제 export 83밤 중 5밤의
깬 시각이 0.15~1.44시간 일렀고, 정오 꼬리 6개 중 2개가 조각 셋 이상이었다.

### ❌ 흔적을 접으려 하지 않는다
관측치에는 `Fold`(SUM/MEAN)가 있지만 흔적에는 없다. "전세자금대출 금리"를
일곱 개 모아 평균 낼 수 없다. 흔적은 쌓이고, 회고가 요약한다.

보여줄 때 줄이는 것은 접기가 아니다. 카드의 `digest`(앱 사용 하루 요약, JAR-019)는 저장하지 않고 볼 때마다
흔적에서 다시 만든다 — 흔적은 그대로 쌓이고, 요약은 보는 방법이다.

## 모듈 지도

| 파일 | 책임 |
|------|------|
| `traces.py` | 흔적 카드 + 레지스트리. 지표 카드의 텍스트판. 하루 요약(`digest`) 자리와 그 요약을 읽는 법(`reading`) — 둘 다 섹터가 단다 |
| `topics.py` | 주제 나무 — 노드·연결, LLM 연산 검사(`plan`: 보여준 흔적만 근거, 이름·자리·합치기·접기는 이유가 있어야), 하이라이트(`trend`: 근거가 있던 날의 분포), 오래 잠잠하면 접기(`stale`), 이번에 깨어난 때(`awakened` → `Standing.since`), 가지까지 합친 최근 근거(`latest`), 관심사 줄기 이름(`TOPIC_FAMILY`) |
| `models.py` | `Observation`·`Insight`(줄기 `family` — 트리거가 단다)·`Severity` + 저장소 프로토콜. 수집 감시의 트리거 이름(`COLLECTION_TRIGGER` — 판단 지시문·`/status` 가 같이 쓴다) |
| `metrics.py` | 지표 카드(`Metric`)와 레지스트리. 숫자 줄 대신 보여줄 말(`describe` — 예보처럼 meta 에 값을 든 관측치를 섹터가 풀어 쓴다) |
| `folding.py` | 원본 → 하루치 관측치. 겹침 병합·기기 중복 제거, 수면의 잠든·깬 시각(가장 긴 잠 덩어리) |
| `config.py` | 환경변수 기반 설정. 비밀값은 `.env` 로만. 웹 검색 주소(`search_base_url` — 비면 검색 끔, 시험 설정은 빈 값). 바깥 API 키(`data_go_key`·`seoul_key`·`kakao_key` — 비면 그 일을 안 한다) |
| `days.py` | 쉬는 날 — 주말과 공휴일(`is_workday`, `holiday`). 공휴일 표는 프로세스에 하나(`set_holidays` — 시작할 때 저장소에서, 날씨 섹터가 새로 받을 때). 트리거가 순수 함수라 인자로 받을 길이 없어서다. 비면 주말만 쉰다 |
| `clock.py` | 시각 규칙 두 가지 — 저장·비교용 UTC 표기(`stamp`), 보여줄 한국 시간(`KST`, `local`). LLM 에게 알려줄 지금(`shown`, 요일까지 — `WEEKDAYS`) |
| `logs.py` | 로그에서 비밀값 지우기. 처리기 거름망이라 다른 로거에서 올라온 기록도 지운다. 주소에 들어가는 키는 세 꼴로(`url_forms` — 받은 꼴·풀린 꼴·다시 싼 꼴) |
| `events.py` | 사건 카드(`EventKind`) + 레지스트리, 점 → 사건 변환(`event_from_point`, 수신구와 옮기기가 같이 쓴다). 사건 이름의 뜻(`labels`·`describe` — 섹터가 단다) |
| `places.py` | 장소 계산 — 거리, 반경 안 가장 가까운 곳, 중심 옮기기. 번호가 바뀌지 않게 하나씩 붙인다 |
