# src/brain/ — 폴더 가이드

## 역할

말을 걸지 정하고, 걸기로 했으면 문장을 만든다. 게이트(싼 필터) → 맥락 조립 →
추론(LLM) → 발화 결정.

**이 폴더가 소유하지 않는 것**: 무엇이 이상인지의 감지(→ `triggers`),
실제 발송(→ `channels`), 데이터 조회(→ `storage`).

---

## 핵심 패턴

### 싼 게이트 먼저, 비싼 LLM 나중
```python
if not self.gate.allows(insight, now):
    return None          # LLM 을 부르지 않는다
```
**이유**: 알림 스팸이 이 프로덕트의 주된 실패 방식이다. 순서를 뒤집으면 30분마다
GPU 를 태우고 결국 "말할 필요 없음" 판정을 받는다.

### 맥락 제공자를 늘려 똑똑하게 만든다
**이유**: 더 큰 모델이 아니다. 2026-08-24 같은 모델·같은 프롬프트에서 수집 현황
제공자 하나를 붙였더니 "배터리 최적화를 확인해라"(존재하지 않는 개념)가
"단축어 설정이 깨졌을 가능성이 높다"로 바뀌었다.

## 금지사항

### ❌ LLM 에게 UTC 시각을 그대로 보여주지 않는다
```python
# ❌ 금지 — f"{t.at:%m-%d %H:%M}"            # 흔적·발화 기록은 UTC 로 저장된다
# ✅ 대신 — f"{local(t.at):%m-%d %H:%M}"     # src/core/clock.py
```
**이유**: 생활 리듬을 읽는 게 이 프로덕트의 일이다. 시각이 9시간 밀리면 낮에 일하는 사람이
새벽에 깨어 있는 사람으로 읽힌다.
**사고 이력**: 2026-10-30. 회고 프롬프트가 낮 12시 56분의 웹 방문을 "03:56"으로, 아침 9시 전에는
"오늘"을 어제 날짜로 보여주고 있었다. 발화 기록(최근 24시간 동안 내가 한 말)도 같았다.

### ❌ 판단을 자유 글로 받지 않는다
```python
# ❌ 금지 — "SKIP 한 단어 아니면 할 말" 을 글자 그대로 받기
# ✅ 대신 — {"speak": true|false, "message": "..."} 로 받고, 깨지면 보내지 않는다
```
**사고 이력**: 2026-10-15 아침 "어제 밤에 이미 아이폰 자동화 점검을 요청했으니 오늘은
중복 알림을 보낸다"가 텔레그램으로 나갔다. 모델이 말하지 않겠다는 판단을 `SKIP` 대신
문장으로 풀어 썼고, 코드는 `SKIP` 으로 시작하지 않으니 할 말로 처리했다.

형식이 깨진 답은 **판단이 아니라 실패**다. 말하지 않기로 한 것처럼 기록하면 쿨다운이
걸려 하루 동안 다시 묻지 않는다. 보내지도 기록하지도 않고, 원문을 경고 로그로 남긴다.

### ❌ 가짜 Insight 를 만들어 넘기지 않는다
```python
# ❌ 금지
probe = Insight(trigger="대화", severity=Severity.INFO, ...)
# ✅ 대신 — assemble(providers, None, now)
```
**사고 이력**: 2026-10-02. 맥락 제공자가 `Insight` 를 필수로 받아서, 대화에서
쓰려고 가짜를 만들었다. 그 가짜는 `observations` 가 비어 있어 추이 제공자가
침묵했고, **자비스는 수면·심박·위치가 멀쩡히 쌓여 있는데도 "데이터 값이 없어서
상태를 판단할 수 없어"라고 세 번 답했다.**

맥락은 "신호에 대한 맥락"이 아니라 **"이 사람에 대한 맥락"**이다. 신호는 선택이다.
타입을 속이면 거짓말이 아래로 전파된다.

### ❌ 플랫폼 지시문에 섹터의 사실을 적지 않는다
```python
# ❌ 금지 — SYSTEM_PROMPT = "... 하루는 새벽 5시에 바뀐다 ..."   # interest 섹터의 DAY_STARTS
# ✅ 대신 — 그 기록의 카드가 읽는 법을 들고 온다(TraceKind.reading), 지시문은 "읽는 법을 따른다"만
```
**사고 이력**: 2026-11-05 JAR-027 리뷰. 보고서 지시문에 하루 요약의 날 경계(새벽 5시)를 적었다. 섹터가 경계를
바꾸면 지시문만 조용히 틀린다 — 모델은 바뀐 요약을 옛 경계로 읽는다. 같은 리뷰에서 사건 이름(`wallet`)의 뜻도
플랫폼이 짐작해 "교통카드 탭"으로 적었는데 실제 설정은 모든 결제였다(낮 결제 7건) — 뜻은 사건 카드(`labels`)에 있다.

### ❌ 줄기를 트리거 이름에서 짐작하지 않는다
```python
# ❌ 금지 — family = insight.trigger.split(":", 1)[0]      # sleep_drop 에는 줄기가 없다
# ✅ 대신 — insight.family (트리거가 단다), 기록에도 family 칸으로
```
**사고 이력**: 2026-11-05 JAR-024 리뷰. 줄기 간격을 `topic:12` 의 앞부분으로 찾았더니 이름에 줄기가 없는 건강
트리거(수면 급감·늦게 잠듦)는 줄기 간격을 영영 안 썼고, 같은 밤을 본 두 신호가 한 주기에 두 말로 나갈 수 있었다
(BACKLOG 4단계 → JAR-029).

### ❌ 찾아본 자료로 답을 생각 없이 쓰게 하지 않는다
```python
# ❌ 금지 — ToolLoop(thinking=False)                  # 찾은 뒤 차례까지 생각 끔
# ✅ 대신 — 첫 차례(찾을지 정함)만 생각 끔, 찾은 뒤 차례는 생각 켬(ToolLoop 기본값)
```
**사고 이력**: 2026-11-05 웹 검색 실측. 생각을 끄고 찾은 자료로 답하게 했더니, 11월에 "2026 하반기 공고는
2026년 3월쯤 나올 것"이라고 지난 달을 말했고, "47회 시험이 11/8 에 있다"고 한 뒤 "올해 남은 회차는 없다"고
앞뒤가 어긋났다. 말투도 자료를 따라 존댓말로 끌려갔다. 생각을 켜니 넷 다 맞게, 반말로 답했다.

### ❌ 큰 재료를 들고 생각하며 찾게 하지 않는다
```python
# ❌ 금지 — tools.run([보고서 지시문, 재료 1.2만 자])      # 차례마다 큰 재료로 생각한다
# ✅ 대신 — research.look("요즘 몰두하는 것: 이름들") 로 찾아 두고, 쓰기는 재료와 함께 생각 없이
```
**사고 이력**: 2026-11-05 실측. 보고서에 도구를 그대로 붙였더니 한 차례가 생각만으로 답 한도(8,192 토큰)를
다 써서 빈 답이 났고, 보고서 하나에 439초가 걸렸다(전에는 30초). 관심사 이름만 들고 찾게 바꾸자 84초.

### ❌ 받은 파일을 자비스 프로세스 안에서 풀지 않는다
```python
# ❌ 금지 — await asyncio.to_thread(files.text_of, data, kind)   # 시간 초과가 나도 스레드는 끝까지 돈다
# ❌ 금지 — zlib.decompress(raw, -15) · zf.read(name)            # 다 푼 뒤에야 크기를 본다
# ✅ 대신 — await files.extract(data, kind)   # 별도 프로세스(메모리·CPU 상한, 넘기면 끝냄), 안에서도 조금씩 풀며 센다
```
**사고 이력**: 2026-11-06 JAR-035 리뷰 재현. 처음엔 분석을 스레드에서 돌리고, 풀었을 때 크기는 파일이 스스로 적은
값(zip 중앙 디렉터리)으로 봤다. 0.3MB HWP 하나가 메모리 666MB 를 쓰고도 "ok"로 끝났고, 크기를 157B 로 속인 3KB
DOCX 와 FAT 가 자기 자신을 가리키는 9KB OLE 는 2.5GB 상한에서 MemoryError 가 났다. 서버는 가용 메모리 4.7GB 에
스왑이 99% 차 있다 — 검색 결과의 첨부 링크 하나로 vLLM·DB 까지 죽을 수 있었다. 시간 상한도 스레드를 못 멈췄다
(PPTX 세 번: 셋 다 시간 초과인데 스레드 셋이 계속 돌며 이벤트 루프가 1.7초씩 멈췄다).

### ❌ 모델이 쓴 주소 글자로 요청하지 않는다
```python
# ❌ 금지 — if _norm(asked) in allowed: page = await reader.read(asked)
# ✅ 대신 — url = state.seen.get(_norm(asked), ""); page = await reader.read(url)   # 받은 그대로의 주소
```
**사고 이력**: 2026-11-06 JAR-035 리뷰 재현. 허용 비교는 정규화한 주소로 하고 요청은 모델이 쓴 글자 그대로
보냈다. 정규화가 끝 빗금을 지우니 `…/f3.pdf////` 가 통과했고 서버는 빗금 넷을 받았다 — 빗금의 수가 곧 값이라,
웹 글에 든 지시로 기록을 조금씩 내보낼 수 있었다. 같은 리뷰에서 첨부를 아무 사이트 링크나 받았더니 블로그 글
하나가 공격자 주소 열 개를 허용 목록에 넣었다(어느 것을 읽느냐가 곧 값) — 첨부는 같은 사이트, 500자, 10개까지.

### ❌ 자식 프로세스의 출력을 끝까지 다 받지 않는다
```python
# ❌ 금지 — out, err = await child.communicate(data)        # 자식이 쏟는 만큼 본체가 모은다
# ✅ 대신 — files._talk: 글은 STDOUT_CAP 까지(넘으면 끝냄), 오류 출력은 끝 STDERR_TAIL 만, 자식은 로깅을 끈다
```
**사고 이력**: 2026-11-06 JAR-035 재리뷰 재현. 분석을 자식 프로세스로 옮겨 메모리 상한을 걸었는데, 부모가
`communicate()` 로 자식의 오류 출력을 다 모았다. pypdf 는 깨진 글꼴 표의 줄마다 그 줄을 통째로 경고로 찍는다 —
87KB PDF 하나에 자식은 325MB 였는데 **본체**가 1.45GB, 90KB·30쪽은 본체가 2GB 를 넘어 죽었다. 격리를 건너뛰어
첫 리뷰의 압축 폭탄과 같은 결과가 본체에서 났다. 자식에서 나오는 통로는 전부 남의 입력으로 보고 상한을 둔다.

### ❌ 크롬의 보안 격리를 끄고 돌지 않는다
```python
# ❌ 금지 — playwright.chromium.launch(...)                       # Playwright 기본값은 격리 끔
# ❌ 금지 — 못 뜨면 chromium_sandbox=False 로 다시 띄우기
# ✅ 대신 — launch(chromium_sandbox=True); 못 뜨면 BrowserUnavailable(이유와 SETUP 안내)
```
**사고 이력**: 2026-11-06 JAR-036 서버 실측. 우분투 26.04 는 권한 없는 사용자 네임스페이스를 AppArmor 로 막아서
(`kernel.apparmor_restrict_unprivileged_userns=1`) 격리를 켠 크롬이 "No usable sandbox!" 로 못 떴고, 격리를 끈
크롬은 그냥 떴다. Playwright 의 기본값이 격리 끔이라 아무것도 안 했으면 조용히 격리 없이 돌았다. 브라우저는
검색 결과의 아무 사이트나 연다 — 격리 없이 크롬 버그 하나면 이 서버의 개인 기록 DB·봇 토큰이 닿는다. 그
크롬에만 네임스페이스를 허락하는 프로필(`deploy/apparmor/jarvis-chromium`, 사용자 sudo)로 푼다.

### ❌ 브라우저가 문(프록시)을 거치지 않고 나가게 두지 않는다
```python
# ❌ 금지 — launch(proxy=None) · bypass 기본값(크롬은 루프백을 프록시에서 뺀다)
# ✅ 대신 — proxy={"server": EgressProxy 주소, "bypass": "<-loopback>"}, QUIC·WebRTC UDP 끔
```
**사고 이력**: 2026-11-06 JAR-036 리뷰 대조 실험. 브라우저는 페이지가 부르는 것(그림·프레임·스크립트)까지 스스로
연다 — 이 서버에는 Langfuse·Open WebUI·clickhouse·자비스 자신(:8100)이 떠 있다. WebRTC·QUIC 설정을 빼고 띄우자
페이지 하나가 STUN 패킷 약 130개를 문을 거치지 않는 UDP 로 127.0.0.1·LAN 에 보냈다(설정을 켜면 0개 —
`test_webrtc_sends_no_udp_around_the_door`). 그 전에도 이름을 따로 풀어 검사하면 그 사이 내부 주소로 바뀌었다
(DNS 리바인딩 — JAR-031 리뷰). 브라우저의 문은 80·443 만 연다.

### ❌ 공개 주소라고 다 밖이라고 보지 않는다(이 집의 공인 주소)
```python
# ❌ 금지 — 사설·루프백·Tailscale 만 막고, 공인 주소는 무엇이든 통과
# ✅ 대신 — web.checked 가 이 집의 공인 주소(web.OWN — 알려 주는 곳에 물어 둔다)도 막는다. 모르면 아무 데도 안 붙는다
```
**사고 이력**: 2026-11-06 JAR-036 리뷰 재현(서버, 운영 코드의 문 그대로). `192.168.55.1:8080` 은 막혔는데 집의
공인 주소 `58.x:8080` 은 공개망이라 통과했고, 공유기가 연결을 안으로 되돌려(NAT 헤어핀) 공유기 로그인 화면과

### ❌ 격리 허용 프로필을 사용자가 고칠 수 있는 경로에 붙이지 않는다

# ❌ 금지 — profile ... /home/*/.cache/ms-playwright/... flags=(unconfined) { userns, }
# ✅ 대신 — root 가 가진 /opt/jarvis/ms-playwright 의 헤드리스 크롬에만. 그 폴더를 우리가 고칠 수 있으면 안 띄운다

### ❌ 다루는 손에게 사용자의 기록을 주지 않는다
```python
# ❌ 금지 — BrowseAgent.run(...) 에 대화·맥락 묶음을 같이 넘기기
# ✅ 대신 — 목표 한 줄과 시작 주소만. 대화로는 정리한 답·출처·파일만 돌아온다
```
**사고 이력**: 2026-11-06 사용자 결정 — 브라우저는 보기·누르기와 사이트 검색창 입력까지 한다. 입력을 주면 웹 글이
"여기에 적어라"로 손을 속여 개인 기록을 그 사이트로 보낼 수 있다(검색어로 새는 것과 같은 종류 — JAR-031
"검색어로 기록이 새는 주입"). 손이 기록을 안 보면 속아도 넣을 것이 없다. 남는 길은 목표 한 줄이고, 그건
부르는 쪽 지시문이 "개인정보는 넣지 않는다"로 막는다.

### ❌ 수집 현황만 주고 값을 빼먹지 않는다
**이유**: `CollectionStatusProvider` 는 "뭐가 수집 중인가"를 알려주고 값은 안 준다.
그것만 있으면 자비스가 자기 데이터를 두고도 판단을 못 한다. `RecentValuesProvider`
가 저장소를 직접 읽어 값을 채운다.

### ❌ 사용자가 물어본 것에 게이트를 걸지 않는다
**이유**: 게이트는 "말을 걸까"를 정하는 장치다. 사용자가 이미 물어봤는데
쿨다운으로 막으면 비서가 아니라 고장난 기계다. `converse.py` 에 게이트가
없는 건 빠뜨린 게 아니다.

### ❌ 명령어 답에 LLM 을 쓰지 않는다
**이유**: "지금 뭘 알고 있나"는 자비스가 생각할 필요가 없는 질문이다.
DB 조회로 즉답이 나오는데 3090 을 데우고 기다릴 이유가 없다.
`/report` 는 명령어 꼴이지만 이 규칙의 대상이 아니다 — DB 조회로 답이 안 나오고 생각을 시키는 요청이다(2~3분 — 다가오는 일정을 먼저 찾는다).

### ❌ 말 안 걸기로 한 판정을 버리지 않는다
```python
# ❌ 금지
if message is None:
    continue              # 아무것도 기록 안 함
# ✅ 대신
    agent.confirm_silence(insight, now, "말 안 걸기로 함")
```
**사고 이력**: 2026-09-29. 재시작 후 20시간 동안 LLM을 **68번 부르고 2번 말했다.**
게이트가 쿨다운을 넘겨 통과시키면 LLM이 SKIP을 내놓는데, 그 판정을 아무 데도 안
남겨서 30분 뒤 똑같이 물어봤다. 수집이 멈춘 상태가 유지되는 한 영원히 반복된다.

**"싼 게이트 먼저, 비싼 LLM 나중"이 여기서 새고 있었다.** 게이트가 LLM을 보호하는
구조인데, LLM의 판정이 게이트로 되돌아오지 않으면 보호가 한 번짜리가 된다.

발송 실패와는 갈라놓아야 한다 — 그건 사고라 다시 시도해야 하고, SKIP은 판단이라
소모돼야 한다. 둘을 같이 취급한 것이 원인이었다.

### ❌ 게이트가 막은 것까지 기록하지 않는다
```python
# ❌ 금지 — loop 에서 None 만 보고 기록
if message is None:
    agent.confirm_silence(...)
# ✅ 대신 — consider() 안에서, LLM 이 판단했을 때만
```
**사고 이력**: 2026-09-30. 위 수정을 넣으면서 **게이트가 막은 경우까지** 같이
기록했다. `consider()` 가 None 을 돌려주는 경우가 둘인데 밖에서는 구별이 안 된다.

막힐 때마다 새 기록이 쌓이고 **쿨다운 시계가 계속 앞으로 밀려서 영영 말을 못 한다.**
SKIP 52건이 0~9분 간격으로 쌓였고 마지막 발화 이후 이틀간 한마디도 못 했다.

기록은 어느 경우인지 아는 자리에서 해야 한다 — `consider()` 안이다.

### ❌ 길이 한도에서 잘린 답을 "형식이 깨졌다"로만 남기지 않는다
```python
# ❌ 금지 — finish_reason 을 안 보고 content 를 그대로 넘긴다 → 부르는 쪽엔 "JSON 을 못 찾았다"
# ✅ 대신 — finish_reason == "length" 면 경고(client.py), 회고는 온전한 앞부분 연산만 건진다(_salvage)
```
**사고 이력**: 2026-11-02 회고 되감기(서버 사본, 87일) 중 3일이 "회고 응답에서 JSON 을 못 찾았다"로 실패했다. 응답은
`{"ops": [` 로 시작해 중간에 끊겨 있었다 — 연산 목록이 응답 상한 8,192 토큰을 넘은 것이다. 흔적이 많은 날(취업 시즌)
이었고, 통째로 버리자 그날 흔적이 다음 날로 밀려 프롬프트가 828줄로 커지고 이튿날 또 잘렸다. 응답 상한을 16,384 로
올리고(프롬프트 글자 상한은 실측 토큰 비율로 맞춰 7.2만 자), 잘리면 앞부분을 적용하고 `cut` 으로 기록한다.

### ❌ 모델 응답을 `str()` 로 감싸지 않는다
```python
# ❌ 금지
return str(choice["message"]["content"])

# ✅ 대신
if not isinstance(content, str) or not content.strip():
    return ""
```
**사고 이력**: 2026-08-21. reasoning-parser 가 붙은 서버는 사고 중 `max_tokens` 에
걸리면 `content` 를 **null** 로 준다. `str(None)` 은 `"None"` 이라는 문자열이 되고,
그게 SKIP 검사와 빈 검사를 둘 다 통과해 사용자에게 발송된다.

### ❌ 신호가 무엇에 대한 것인지(`at`)를 글자로만 견주지 않는다
```python
# ❌ 금지 — about == insight.at 인 기록이 있는가
# ✅ 대신 — 같은 about 이거나, insight.at 보다 뒤에 판단한 기록이 있는가(SpeechLog.judged_since)
```
**사고 이력**: 2026-11-05 JAR-024 리뷰 재현. 관심사의 `at` 은 "이번에 깨어난 때"(첫 근거)인데, 회고는 안 붙은 흔적을
7일 동안 다시 보여주고 다음 날 더 이른 흔적을 붙인다. 깨어난 때가 11-03 에서 11-01 로 당겨지자 글자가 달라져
**같은 관심사를 다음 날 또 보냈다**(LLM 2번, 메시지 2개). 판단은 신호의 때보다 늘 뒤라 "그 뒤에 판단했나"는 밤·아침
사건에도 같은 답을 내고, 판단 시각을 `at` 으로 쓰는 수집 감시는 늘 새 신호로 남는다.

### ❌ 수집 경고를 👎 로 재우지 않는다
```python
# ❌ 금지 — 판단 지시문의 "👎 한 말과 비슷하면 말하지 않는다"를 수집 경고에도
# ✅ 대신 — 👎 규칙은 사람 신호에만. 수집 경고는 예전 지시문 그대로, 반응도 판단 맥락에 안 넣는다
```
**사고 이력**: 2026-11-05 JAR-026 리뷰. 먼저 건 말 53번 중 51번이 수집 경고라 첫 👎 는 거기 떨어지기 쉽다. 그
👎 가 30일 동안 매일 "비슷하면 말하지 않는다"와 함께 들어가면 끊김이 길어져도 감시견이 잔다 — 2026-08-29 "중단이
심해질수록 감시견이 조용해졌다"(triggers/_GUIDE)와 같은 모양이다. 수집 경고의 👎 가 무엇을 뜻할지는 사용자가 정한다.

### ❌ "같은 밤"을 쿨다운 길이로 흉내 내지 않는다
```python
# ❌ 금지 — "late_sleep": timedelta(hours=16)   # 같은 밤을 하루 한 번으로 만들려고 늘린다
# ✅ 대신 — 판단 기록에 about=insight.at 을 남기고, 게이트가 같은 신호면 막는다
```
**사고 이력**: 2026-11-02 JAR-018 리뷰 재현(30분 주기, 두뇌는 매번 말 안 걸기로). 쿨다운만으로 막으면
07:30 에 들어온 밤을 6시간마다 세 번 물었다. 16시간으로 늘리자 그날 23:30 에 한 번 더 묻고, 그 판단이
쿨다운을 밀어 **다음 날 아침의 새 밤이 15:30 에야** 판단됐다. 시간 길이는 "같은 것"의 대용품이 못 된다.
신호의 `at` 이 판단 시각인 것(수집 감시)은 늘 새 신호라 전처럼 쿨다운만 본다.

### ❌ 발송 전에 쿨다운을 기록하지 않는다
**사고 이력**: 발송 실패까지 기억에 남기면 사용자는 메시지를 못 받았는데 자비스는
"아까 말했지" 하고 쿨다운 내내 침묵한다. `confirm_spoken` 은 **성공 후에만** 부른다.

### ❌ 맥락 제공자 하나가 죽었다고 발화를 포기하지 않는다
**사고 이력**: 캘린더 서버가 내려갔다고 건강 알림까지 멈추면 안 된다.
`assemble()` 은 제공자별로 예외를 삼키고 나머지를 모은다.
