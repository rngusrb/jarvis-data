# src/sectors/commute/ — 폴더 가이드

## 역할

이동 패턴을 소유한다. 위치 자동화가 주는 것은 **사건**(언제·어디서·왜)이다 —
`events.py` 의 위치 카드. 퇴근·출근 시각처럼 "하루에 숫자 하나"인 것만 관측치다.

**이 폴더가 소유하지 않는 것**: 접는 계산(→ `core/folding`), 판단 실행(→ `brain`),
다른 섹터. health 의 수면 데이터를 참조하지 않는다.

---

## 핵심 패턴

### 값이 곧 시각이다
```
17.5  →  오후 5시 30분
```
**이유**: 수면·심박은 측정 표본이지만 퇴근은 **사건**이다. 측정값을 집계하는 게
아니라 "언제 일어났나"가 값이다.

### 위치는 사건이다 — 접지도, 숫자로 담지도 않는다
```python
LOCATION = EventKind(kind="location", value_as="accuracy", ...)   # events.py
Event(label="wallet", lat=…, lon=…, meta={"accuracy": …})        # 사건 표
```
**이유**: 위치는 "9시에 여기, 18시에 저기"가 낱낱이 남아야 패턴이 보인다. "하루 평균
위치"는 의미가 없고, 숫자 칸(관측치)에 담으면 숫자로 취급된다.
**사고 이력**: 2026-08-25 ~ 10-02 위치를 `Fold.RAW` 관측치로 담았다. 값이 없어 74건 전부
0 이었고, 자비스의 "최근 값"에 "위치 0 · 0 · 0" 이 들어갔다. 2026-11-02 사건 표로 옮겼다
(`app/migrate.py`). 폰 단축어는 그대로 표본 모양으로 보내고, 서버가 갈라 담는다.

### 위치에는 어느 자동화가 보냈는지 라벨을 붙인다
```json
"meta": {"lat": ..., "lon": ..., "trigger": "wallet"}    ← 사건의 label 이 된다
```
**사고 이력**: 2026-08-26. 하루에 위치가 6개 찍혔는데 `떠날 때` 는 한 번만 발동한다.
지갑 자동화가 섞였다는 뜻인데 **어느 점이 카드 탭인지 구분할 수 없었다.**
좌표만으론 "집을 나선 지점"과 "교통카드를 찍은 지점"이 같아 보이고, 후자가 곧
'타는 곳'이라 그 구분이 이 섹터의 핵심 정보다.

### 하루에 여러 번이면 하나만 고른다
```
퇴근      Fold.LAST    나갔다 들어와도 마지막이 퇴근
출근 도착  Fold.FIRST   처음 도착이 출근
```
**이유**: 평균을 내면 3시와 7시 사이 어딘가라는, **실제로 일어나지 않은 시각**이 나온다.

## 금지사항

### ❌ 절대 기준으로 야근을 판정하지 않는다
```python
# ❌ 금지
if departure > 19.0: alert("야근")
```
**사고 이력**: 수면에서 이미 겪었다 (2026-08-21, "7시간 미만" 기준이면 88%의 날에 알림).
6시 퇴근이 평범한 사람과 9시 퇴근이 평범한 사람에게 같은 기준을 대면 한쪽은 매일
울리고 다른 쪽은 영영 안 울린다.

### ❌ 주말을 baseline 에 넣지 않는다
**이유**: 주 5일 패턴을 가진 사람의 "평소"는 평일로만 만들어야 한다.
주말 기록 하나가 평균을 몇 시간씩 끌어내린다. 공휴일도 같다 — 평일은 `core/days.is_workday` 로 가린다
(JAR-043, 추석 연휴의 늦은 아침을 "평소보다 늦게 나섬"으로 읽지 않게).

### ❌ 끊김 기준을 수면과 같게 두지 않는다
```python
stale_after = timedelta(days=4)   # 수면·휴식기 심박은 42시간(밤 단위)
```
**이유**: 위치·퇴근은 평일에만 생기는 사건이고 주말·휴가·재택에 자연히 빈다.
수면 기준(36시간 → 2026-11 부터 42시간)을 쓰면 **매주 월요일마다** 수집이 멈췄다고 잔소리한다.

---

### ❌ 열차 알림에 판단 모델이 고를 열차를 남기지 않는다
```python
# ❌ 금지 — 두 방향 다, 역에 닿기 전 열차까지, "8분 후 (참나무)" 원문 그대로, 라벨에 "동끝행 - 동녘방면"
# ✅ 대신 — 평소 방향(usual_way)만, 탈 열차는 시간표로 놓침·빠듯·여유를 갈라(plan) 줄마다 행선지·예상 시각 하나, 라벨엔 방향 이름 없이
```
**사고 이력**: 2026-11-11 JAR-043~044 리뷰. 판단 모델이 6번 중 4~5번 틀린 열차를 안내했다 — 역에 닿기 전에
떠나는 열차를 "바로 탈 수 있다", 괄호 속 지금 위치(참나무)를 행선지로, 반대 방향(서끝행)을 권함. 고친 뒤에도
라벨의 "동끝행"(8번 중 1번)·"동녘방면"(8번 중 2번 — "동녘행")을 탈 열차로 읽었다. 2차 리뷰(BLOCKED): 실시간은
방향마다 다음 두 열차만 줘서, 버스 탭 순간(역까지 6~7분)에 보이는 두 열차가 출근 시간 배차(2.5~4분) 때문에 늘
역에 닿는 무렵에 왔다 — "탈 수 있다"를 정할 수 없었다. 사용자 결정(2026-11-11): 시간표로 세 번째 열차부터 안다.

### ❌ 카카오의 역 이름으로 실시간 도착을 바로 믿지 않는다
```python
# ❌ 금지 — fetch_arrivals(client, key, "가람")          # 카카오 "가람역 5호선"의 앞부분
# ✅ 대신 — api_name(...) → "가람(새터)"                # 없으면 모든 역(ALL)에서 정식 이름을 찾는다
```
**사고 이력**: 2026-11-11 열차 알림을 붙이며 재 보니 "가람"으로 물으면 "해당하는 데이터가 없습니다"였다
(나루는 나왔다). 이 API 는 부제가 붙은 역을 "가람(새터)", "솔밭(공원앞)"로만 안다 — 그대로
쓰면 그 역을 지나는 사람에게만 조용히 열차 알림이 안 갔을 것이다.

## 모듈 지도

| 파일 | 책임 |
|------|------|
| `metrics.py` | 퇴근/출근 시각 카드 (수집기 없음) |
| `events.py` | 위치 사건 카드. 2026-11 관측치에서 옮겼다 — 값이 없는 것을 숫자 칸에 담고 있었다. 사건 이름의 뜻 — SETUP 2-5 를 따른다(leave_home → 등록한 곳(집·직장)을 벗어남, wallet → 지갑 탭(교통·결제)) |
| `places.py` | 장소의 역할 후보(집·아침에 타는 곳·내리는 곳·저녁에 타는 곳). 평일(공휴일 빼고), 한국 시각, 사흘 이상. 집의 좌표(`home_spot`, 저장소에서 42일치로 `home_now`) — 날씨 섹터가 조립을 거쳐 쓴다 |
| `triggers.py` | 사건 트리거 둘(줄기 `commute` — 나선 때와 탄 때가 따로 들어와도 줄기 간격으로 한 아침에 한 말) — 평일(공휴일 빼고) 아침 평소보다 늦게 나섬, 평소와 다른 곳에서 첫 탑승. 관측치 트리거는 없다. 열차 알림(`TrainAheadTrigger`, 줄기 `train`) — 평일 아침 나서자마자(버스 → 지하철이면 타는 곳 첫 탭, 아니면 집 나섬) 10분 안, 탈 역에 닿는 범위(최근 평일 걸린 시간의 가장 짧은~긴 것)와 내리는 곳을 신호 이름에 싣는다(`train_ahead:<역>:<내리는 곳>:<빠른 HHMM>:<늦은 HHMM>`) |
| `inspect.py` | 쌓인 위치 사건을 훑어보는 도구. 패턴이 있는지부터 확인 (시간대는 한국 시각) |
| `kakao.py` | 카카오 로컬 — 반경 안 가장 가까운 지하철역(`nearest_station`), 동네(`region`), 역 이름으로 역의 자리(`station_spot` — 열차 방향을 정할 때, 역 이름만 보낸다). 키는 머리말로 — 주소에 안 든다 |
| `naming.py` | 장소 이름 붙이기(`PlaceNaming`, 서버가 6시간마다) — 역할이 있는 장소 중 이름 없는 곳에 역 이름(200m 안) 또는 동네 이름. 집 장소는 장소 번호로 거른다(역할 이름으로 거르면 집이 다른 역할을 겹쳐 가질 때 집 좌표가 나갔다 — 리뷰), 집에서 수백 m 인 정류장 좌표는 나간다. 사람이 붙인 이름이 이긴다 |
| `subway.py` | 서울 실시간 지하철(HTTP 만 된다 — https 는 시간 초과, 키와 역 이름이 평문으로 나간다) — 카카오 역 이름 읽기(`parse_station`), 이 API 의 정식 이름 찾기(`api_name` — 부제 붙은 역), 받기(`fetch_arrivals` — 열차번호 `btrainNo` 까지), 평소 방향(`usual_way` — 다음 역이 내리는 곳에 가까워지는 쪽, 모르면 None), 탈 열차 줄(`render_plan` — "동갈래행 07:12쯤(빠듯 — 빨리 닿는 날만 탄다)"), 열차 알림 준비(`TrainArrivals` — 실시간은 방향·지금 늦음만, 탈 열차는 시간표로. 역이 아니거나 방향·시간표·여유 있는 열차를 모르면 None, 라벨에 방향 이름을 안 적는다, 못 찾은 역 자리는 기억하지 않는다) |
| `timetable.py` | 서울 열린데이터 지하철 시간표(일반 인증키, HTTP 만) — 역 번호(`station_code` — "가람"·"05호선" → 1234), 평일 시간표(`timetable` — 상행·내선 1, 하행·외선 2, 첫 역은 출발 시각, 자정 넘은 막차는 뺀다), 지금 늦음(`lateness` — 실시간 열차번호를 시간표와 맞춘 차이의 중앙값, 30분 넘으면 다른 회차), 열차 가르기(`plan` — 승강장에 닿는 범위 앞은 뺌, 안은 빠듯, 뒤는 여유 두 대까지) |
