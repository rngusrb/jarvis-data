# src/sectors/money/ — 폴더 가이드

## 역할

쓴 돈을 본다 — 카드 승인 문자·애플페이 결제를 받아 같은 결제를 하나로 세고, 오늘·어제·이번 주·지난주·이번 달
합계를 자비스의 맥락에 넣는다. **보기만 한다**: 돈을 움직이는 기능(이체·결제·카드 설정)은 없고 만들지 않는다
(사용자 결정, 2026-11-11 스프린트 계획).

은행·카드 API(마이데이터·오픈뱅킹)는 사업자만 받을 수 있다. 그래서 결제는 폰이 보낸다(SETUP 2-9).

**이 폴더가 소유하지 않는 것**: 흔적 저장(→ `storage/traces`), 받는 문(→ `runtime/ingest`, `/ingest/traces`),
맥락에 언제 넣는지(→ `app/main.py` 조립), 말할지 판단(→ `brain`).

## 핵심 패턴

### 원문을 쌓고 볼 때 읽는다
```python
Trace(kind="card_sms", text=<문자 본문>)  # 받을 때 읽지 않는다 → payments.read 가 볼 때마다
```
**이유**: 읽는 법을 고치면 지난 결제까지 바로 고쳐 읽힌다. 받을 때 숫자로 접으면 잘못 읽은 금액과 두 길로
두 번 센 결제를 되돌릴 수 없다. 결제는 숫자지만 관측치(접는 값)가 아니라 흔적이다.

### 합계와 기간은 코드가 센다
**이유**: 모델에게 결제 목록을 주고 더하라고 하면 틀린다. 생각 루프에서 날짜 세기를 모델에게 맡겼다가 리뷰에서
여섯 번 막힌 것과 같은 종류다(2026-11-11). "이번 주"(월요일부터)도 여기서 정하고, 맥락 라벨에 "다시 더하지
말고 이대로 말한다"를 적는다.

### 못 읽으면 짐작하지 않고 센다
**이유**: 결제 금액이 하나로 안 남는 문자(해외 승인, 결제 예정 안내, 금액 둘)를 짐작해 넣으면 틀린 합계가
조용히 나간다. 합계에서 빼고 "결제로 못 읽은 기록 N건"으로 보인다. 거절 문자는 결제가 아니라 세지도 않는다.

### 같은 결제는 다른 길끼리만 합친다
금액이 같고 5분 안이면 문자 + 애플페이를 하나로(가맹점·카드는 문자 쪽, 때는 둘 중 이른 쪽).
**이유**: 같은 길로 온 같은 금액 둘은 정말 두 번 산 것일 수 있다(커피 두 잔을 따로). 단, **본문이 똑같은
문자**는 같은 문자가 두 번 들어온 것으로 본다 — 대가: 누적·잔액이 안 붙는 꼴이면 같은 분·같은 가게·같은 금액의
두 결제가 하나가 된다(2차 리뷰가 적어 두라 함).

### 받기 시작한 날 전은 모른다고 적는다
**이유**: 11/5 부터 받았는데 "이번 달 N원"이면 달 전체로 읽힌다. 기간이 받기 전과 걸치면 "○○부터 받은 것만",
통째로 전이면 "받기 전이라 모름".

## 금지사항

**문자 꼴은 실제 문자로 확인하기 전이다**(2026-11-12): 테스트의 문자는 카드사 문자에 흔한 꼴을 본뜬 것이라,
사용자 예시를 받으면 그걸로 바꾸고 어긋난 데를 고친다. 아래 넷은 모두 같은 날 JAR-045 1차 리뷰가 재현한 것이다.

### ❌ 끊긴 수집을 "0원"으로 보이지 않는다
```python
# ❌ 금지 — 받은 결제만으로 "오늘 0건 0원"
# ✅ 대신 — 첫 줄에 길마다 마지막으로 받은 때, 이틀 넘었으면 "그 뒤는 모른다"(_last_line)
```
**이유**: 라벨이 "이대로 말한다"고 지시하고, 수집 현황은 끊김 기준(14일) 동안 "정상"이다.
**사고 이력**: 매일 오던 결제가 11/3 에 멈춘 경우를 재현하자 11/12 블록이 "오늘·어제·이번 주 0건 0원"을 냈다.

### ❌ 결제라고 짐작해 세지 않는다
```python
# ❌ 금지 — "승인"이 있고 금액이 하나면 결제 / 좁은 정규식으로 "안내 속 취소"를 골라내기
# ✅ 대신 — 확실한 꼴만 읽는다: 승인취소·"(1234)취소"는 취소, "승인거절·승인실패"는 거절(따로 센다).
#           그 밖의 자리에 취소·거절·실패·불가가 있거나 환불·대출·카드론·현금서비스·리볼빙이면 못 읽음(보인다).
#           때(월/일 시:분)와 결제 금액 하나가 있어야, 지갑은 원화·양수여야. 때·금액이 없는 안내 문자는 결제가 아니다
```
**사고 이력**: 1차 리뷰 — "승인 났어? 회비 30,000원 보냈어" → +30,000, 대출 승인 → +30,000,000, "환불승인
12,000원" → +12,000, 승인 문자 끝의 "취소문의 1588-…" → −4,500, 애플페이 "$12.00" → 12원, "-₩4,500" → +4,500.
그래서 좁힌 정규식이 2차 리뷰에서 새로 틀렸다 — "승인취소 안내" → +4,500, "승인이 거절됨" → +9,000, "카드론 승인"
→ +3,000,000, 가맹점 "불가리"는 거절로 흔적 없이 사라짐. 예외를 정규식으로 쌓지 않고, 확실하지 않으면 못 읽음으로
보인다. 실제 문자 예시를 받으면 그 꼴을 확실한 쪽에 더한다(지금 확실한 꼬리 안내는 "취소문의" 하나).

### ❌ 같은 것이 두 번 오면 두 번 세지 않는다
```python
# ❌ 금지 — 흔적 줄마다 결제 하나
# ✅ 대신 — 본문이 같은 문자는 하나로, 10초 안의 같은 애플페이 값은 하나로(read)
```
**이유**: 흔적 저장소는 (출처, 종류, 때, 글)이 같아야 하나로 본다. 때가 1초만 달라도 둘이다.
**사고 이력**: `/ingest/traces` 로 같은 문자를 1초 차이로 두 번 넣자 4,500원 하나가 "2건 9,000원"이 됐다.

### ❌ 두 길을 합칠 때 늦은 쪽 때를 쓰지 않는다
**사고 이력**: 문자 23:59 와 애플페이 00:00:10 을 합치며 애플페이 때를 쓰자 다음 날·다음 주로 넘어갔다. 둘 중
이른 쪽을 쓴다. 받기 시작한 날도 받은 때와 결제한 때 중 이른 쪽이다(11/4 23:58 결제를 11/5 00:01 에 받음).

## 모듈 지도

| 파일 | 책임 |
|------|------|
| `payments.py` | 결제 하나(`Payment` — 취소는 음수), 문자 읽기(`from_sms` — 승인·취소, 누적·잔액·할인 금액 빼기, 때 뒤의 가맹점, 해 넘김), 애플페이 읽기(`from_wallet` — 단축어가 넘긴 금액·가맹점·카드), 못 읽은 수까지(`read`), 두 길의 같은 결제 합치기(`merge`), 기간 합계(`summarize`) |
| `traces.py` | 흔적 카드 둘 — `card_sms`, `wallet_payment`(민감, 회고에서 뺌, 결제 없는 날이 흔해 끊김은 14일, 거쳐 오는 곳은 다른 폰 종류와 같은 `아이폰` — 수집 감시가 묶어 원인을 짚는다) |
| `context.py` | `SpendingProvider` — 쓴 돈 맥락(길마다 마지막으로 받은 때, 40일을 읽어 세고, 받기 시작한 날은 한 해치에서). 결제 흔적이 한 해 동안 하나도 없으면 안 보인다. 대화·판단·`/report` 가 같이 본다 |
