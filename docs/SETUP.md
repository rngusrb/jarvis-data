# SETUP — 처음부터 돌리기까지

자비스는 **네 조각**이 따로 돈다. 하나씩 세우고 각 단계 끝에서 확인한다.

```
아이폰 단축어  ──HTTP──┐
맥 수집기      ──HTTP──┼──→  자비스 서버 (8100)  ──→  vLLM (8000)
                       │              │
                       │              └──→  텔레그램
                    (Tailscale)
```

> ⚠️ **데이터는 공유하지 않는다.** `data/*.db` 에는 수면·위치·브라우저 기록이
> 들어 있고 gitignore 되어 있다. 같이 개발하더라도 **각자 자기 인스턴스를
> 돌린다.** 코드는 공유하고 데이터는 안 한다.

---

## 0. 무엇이 필요한가

| | 왜 |
|---|---|
| 리눅스 서버 (GPU) | vLLM + 자비스 상주. 노트북은 자면 데이터가 샌다 |
| 아이폰 + 애플워치 | 수면·심박·위치의 출처 |
| 맥 (선택) | 브라우저 기록 수집기가 여기서 돈다 |
| Tailscale | 폰이 집 밖에서도 서버에 닿아야 한다 |

**GPU가 없으면** vLLM 대신 다른 OpenAI 호환 서버를 `JARVIS_BRAIN_URL` 에
꽂으면 된다. 자비스는 `/v1/chat/completions` 만 쓴다.

## 1. 서버 세우기

```bash
git clone git@github.com:rngusrb/jarvis-data.git ~/jarvis-data
cd ~/jarvis-data
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env    # 없으면 아래 표 보고 직접 만든다
```

### .env

| 키 | 설명 |
|----|------|
| `JARVIS_BRAIN_URL` | vLLM 주소. 기본 `http://localhost:8000` |
| `JARVIS_BRAIN_MODEL` | 비우면 `/v1/models` 로 자동 탐색 |
| `JARVIS_INGEST_TOKEN` | **직접 만든다.** `openssl rand -hex 32` |
| `JARVIS_TELEGRAM_BOT_TOKEN` | 비우면 콘솔로 출력 |
| `JARVIS_TELEGRAM_CHAT_ID` | 위와 같음 |
| `JARVIS_LOOP_INTERVAL_SEC` | 기본 1800 |

**토큰은 각자 만든다.** 남의 토큰을 받아 쓰면 그 사람 서버에 데이터를 쏜다.

### 확인

```bash
.venv/bin/python scripts/harness.py all      # 이게 이 레포의 "완료" 기준
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8100
curl -s localhost:8100/health | python3 -m json.tool
```

### 상주시키기

```bash
sudo tee /etc/systemd/system/jarvis.service <<'EOF'
[Unit]
Description=jarvis
After=network-online.target

[Service]
User=%i
WorkingDirectory=/home/YOURNAME/jarvis-data
ExecStart=/home/YOURNAME/jarvis-data/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8100
Restart=always

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now jarvis
```

**vLLM도 자동 기동을 켠다.** 도커로 돌린다면:

```bash
docker update --restart unless-stopped vllm
```

> 사고 이력: 컨테이너를 새 이미지로 다시 만들면 이 정책이 `no` 로 돌아간다.
> 이미지를 올린 뒤에는 다시 걸어야 한다.

## 2. 아이폰 단축어 — 여기가 제일 손이 많이 간다

폰 설정은 코드로 관리할 수 없다. 이 절이 유일한 기록이다. **블록 단위로 적는다** —
"건강 데이터를 보내는 단축어를 만든다"는 설명으로는 아무도 못 만든다.

> 이 절은 2026-08-24에 만든 별도 가이드와 그 뒤 한 달의 시행착오를 합친 것이다.
> 그 가이드는 레포 밖에 있었고 서버 주소·지표가 낡아 있었다 — **레포 밖 문서는
> 반드시 낡는다**는 게 이 절을 여기 둔 이유다.

### 2-0. 먼저 통신이 되는지

아이폰 Safari에서 `http://<서버 IP>:8100/health` 를 연다. JSON이 보이면 된다.

안 보이면 ① 폰·서버 양쪽 Tailscale, ② 서버가 `--host 0.0.0.0` 으로 떴는지 확인한다.

### 읽는 법

가장 헷갈리는 건 **타이핑할 글자**와 **삽입할 변수**의 구분이다.

```
{"start":          ← 손으로 타이핑
⟨포맷 지정된 날짜⟩   ← 변수 삽입 (파란 알약)
```

대괄호 `[ ]` 와 따옴표 `"` 는 **진짜로 타이핑하는 글자**다. 변수를 감싸는 표시가 아니다.

---

### 2-1. 수면 — 구간을 통째로 보낸다

`POST /ingest/spans`

```
1. 건강 샘플 찾기
     유형     수면
     시작일   최근 1일
     값 필터  지운다

2. 각 항목 반복  ─── 아래 7개는 반복 안에 ───

   3. 건강 샘플 세부사항 가져오기 → 시작일
   4. 날짜 포맷 지정              ISO 8601 · 시간 포함 켜기
   5. 건강 샘플 세부사항 가져오기 → 종료일
        ⚠️ 입력이 "반복 항목"인지 확인. 앞 액션 결과가 자동으로 물린다
   6. 날짜 포맷 지정              ISO 8601 · 시간 포함 켜기
   7. 건강 샘플 세부사항 가져오기 → 값
   8. 텍스트
        {"start":"⟨포맷 지정된 날짜⟩","end":"⟨포맷 지정된 날짜⟩","stage":"⟨값⟩"}
        ⚠️ 변수 목록에 "포맷 지정된 날짜"가 둘 뜬다. 위가 시작일, 아래가 종료일
   9. 변수에 추가 → rows

10. 텍스트 합치기     입력 rows · 구분자 사용자 지정 → ,
11. 텍스트            {"spans":[⟨합쳐진 텍스트⟩]}
        ⚠️ 대괄호는 직접 타이핑한다. 합쳐진 텍스트에 배열 껍데기가 없다
12. URL 콘텐츠 가져오기
        URL    http://<서버 IP>:8100/ingest/spans
        방식   POST
        헤더   Authorization: Bearer <토큰>
               Content-Type: application/json
        본문   파일 → 11번 텍스트
        ⚠️ 본문 요청을 "JSON"으로 두면 422가 난다. "파일"이어야 한다
```

성공하면:

```json
{"written":1,"observations":[{"kind":"sleep_hours","value":2.24,"segments":16}],
 "stages":["깨어 있는 시간","수면 시간"]}
```

`segments` 가 10~20이면 제대로 온 것이다. `stages` 에는 걸러낸 것까지 전부 찍힌다 —
`written: 0` 일 때 무엇이 도착했는지 보이게 하려는 것이다.

> **왜 합산해서 보내지 않나**: 조각 수가 측정 품질 신호다. 폰이 "4.7시간"만 보내면
> 그 정보가 사라지고 측정 실패한 밤을 걸러낼 수 없다. 그리고 백필(`export.xml`)과
> **같은 집계 코드**를 지나가야 한다 — 계산이 두 군데 살면 경로에 따라 값이 어긋난다.

### 2-2. 휴식기 심박 — 점만 보낸다

`POST /ingest/samples`. 수면 단축어를 **복제**한 뒤 세 곳만 바꾼다.

```
1. 건강 샘플 찾기 → 유형 "휴식기 심박수" · 시작일 최근 1일
2. 각 항목 반복
   3. 건강 샘플 세부사항 가져오기 → 시작일
   4. 날짜 포맷 지정  ISO 8601 · 시간 포함
   5. 건강 샘플 세부사항 가져오기 → 값
   6. 텍스트   {"at":"⟨포맷 지정된 날짜⟩","value":⟨값⟩}
        ⚠️ value 는 숫자다 — 따옴표를 씌우지 않는다
   7. 변수에 추가 → rows2
8. 텍스트 합치기  입력 rows2 · 구분자 ,
9. 텍스트   {"kind":"resting_heart_rate","samples":[⟨합쳐진 텍스트⟩]}
10. POST /ingest/samples
```

> **원본 심박(`심박수`)을 쓰지 않는다.** 하루 표본이 361개(최대 1,157개)라 단축어가
> 반복을 끝내지 못하고 멈춘다. 게다가 HealthKit 그룹화는 평균이 아니라 **합계**로
> 묶어서 심박이 13,732로 온다. 워치가 이미 계산해두는 휴식기 심박은 하루 1개다.
>
> **걸음수도 같은 벽에 부딪혀 접었다.** 워치가 운동 중에는 초 단위로 기록해서 하루
> 표본이 3개~1,112개로 널뛴다. 평상시 30~80개라 며칠은 통과하다가 운동한 날 멈춘다.

### 2-3. 한 단축어에 이어 붙이기

단축어를 둘 만들 필요는 없다. 수면 단축어 **아래에 이어 붙이면** 순서대로 전송한다.

```
수면        찾기 → 반복 → 합치기 → POST /ingest/spans
휴식기 심박  찾기 → 반복 → 합치기 → POST /ingest/samples
```

> ⚠️ **`rows` 변수를 재사용하면 앞 데이터가 섞인다.** 두 번째는 `rows2` 로 이름을 나눈다.
>
> ⚠️ **반복 안에서 "변수 설정"을 쓰면 갱신이 안 된다.** 같은 값이 N번 반복된다.
> 액션 결과를 직접 참조하고 "변수에 추가"를 쓴다.

### 2-4. 위치 — 감싸개 하나 + 자동화별 한 줄

자동화마다 HTTP 단축어를 만들면 개수가 폭발한다. **쏘는 단축어는 하나만** 두고,
자동화가 "누가 불렀는지"를 라벨로 넘긴다.

`이동감지` 단축어:

```
1. 입력으로 "텍스트"를 받기          ← 라벨이 여기로 들어온다
2. 현재 위치 가져오기
3. 텍스트
   {"source":"shortcuts","kind":"location","samples":[
     {"at":"⟨현재 날짜 ISO 8601⟩","value":0,
      "meta":{"lat":⟨위치 위도⟩,"lon":⟨위치 경도⟩,
              "trigger":"⟨단축어 입력⟩"}}]}
4. POST /ingest/samples   (헤더·본문은 2-1의 12번과 같다)
```

그리고 자동화마다 **한 줄짜리 감싸개**:

```
[leave_home]  텍스트 "leave_home" → 이동감지 실행 (입력: 텍스트)
[wallet]      텍스트 "wallet"     → 이동감지 실행 (입력: 텍스트)
```

> `trigger` 라벨이 없으면 위치가 한 덩어리로 섞여서 "집을 나선 지점"과 "카드를 찍은
> 지점"을 구별할 수 없다. **이 라벨이 타는 역을 찾아낸 열쇠였다** — `wallet` 이 몰리는
> 좌표가 역이고, 아침에 사라진 그 지점에서 저녁에 2m 오차로 다시 나타났다.

### 2-5. 자동화 걸기

`단축어 앱 → 하단 자동화 탭 → 우측 상단 +`

| 자동화 | 트리거 | 감싸개 |
|--------|--------|--------|
| **수면** | 수면 → **기상할 때** | (감싸개 없음. 직접) |
| **떠날 때** | 집·직장을 벗어날 때 (지오펜스) | `leave_home` |
| **지갑** | 탭할 때 → 카드·티머니 전부 선택 | `wallet` |

모두 이렇게 설정한다:

```
즉시 실행        ✓   ← 안 켜면 매번 알림을 눌러야 해서 자동화가 아니게 된다
실행되면 알리기   ✓   ← 켜두는 게 좋다 (아래 이유)
```

> **"실행되면 알리기"를 켜는 이유**: 자동 수집의 흔한 실패는 요란한 에러가 아니라
> **침묵**이다. 저 알림이 "살아 있음"을 매일 공짜로 알려준다.

**지갑 자동화의 카테고리는 전부 체크한다.** 음식·쇼핑·여행·서비스·엔터·의료·교통.
티머니가 Wallet에 있으면 **교통 탭도 잡혀서** 그게 이동 데이터가 되고, 나머지는
나중에 소비 데이터가 된다.

### 검토했지만 안 쓴 것들

동료가 다시 제안하지 않도록 이유를 남긴다.

| | 왜 안 썼나 |
|---|---|
| **Wi-Fi 연결/해제** | 지오펜스보다 좋아 보였는데, iOS 버전마다 "해제"가 없다. 연결만 잡히면 나가는 걸 못 잡는다 |
| **블루투스** | 에어팟 연결은 나가기 **직전** 신호다. 보조로는 쓸 만하지만 단독으로는 부정확 |
| **Apple Watch 운동** | 걷기 자동 감지가 **몇 분 늦고** 사용자 수락이 필요하다. "지금 나가려 한다"를 잡기엔 늦다 |
| **"움직임 감지"** | iOS에 그런 트리거가 없다 |
| **자체 iOS 앱** | `HKObserverQuery` + 백그라운드 전송은 가능하지만 대부분 타입이 최소 1시간 주기다. 단축어 이벤트와 실시간성이 비슷한데 Xcode가 필요하다 |

---

### 2-6. 자동화가 뭘 넘기는지 모를 때

새 자동화를 붙이기 전에 **블록 하나짜리 진단 단축어**로 확인한다.

```
⟨단축어 입력⟩ 빠른 보기
```

`빠른 보기` 액션을 추가하고 입력 칸에 변수 `단축어 입력`을 꽂는다. 이게 전부다.
자동화가 이 단축어를 실행하게 걸어두면 **무엇이 들어오는지 화면에 뜬다.**

지갑 자동화가 금액·가맹점·카테고리까지 넘기는지 이걸로 확인할 수 있다. 넘긴다면
결제 문자 파싱이 통째로 필요 없어진다.

### 2-7. 막혔을 때

| 증상 | 원인 |
|------|------|
| `401` 토큰 불일치 | `Bearer` 뒤 **한 칸**이 빠졌거나 토큰 오타 |
| `503` | 서버 `.env` 의 `JARVIS_INGEST_TOKEN` 이 비어 있다 |
| `422 invalid character in year` | 날짜 변수가 목록으로 잡혔거나 따옴표 밖에 있다 |
| `422` 그 외 | 본문 요청이 **JSON** 으로 돼 있다 — **파일**이어야 한다 |
| `400` | `kind` 오타. 서버가 집계법을 모른다 |
| `written: 0` | 전부 걸러졌다. 응답의 `stages` 를 본다 |
| 연결할 수 없음 | 폰 Tailscale 꺼짐, 또는 서버에 `--host 0.0.0.0` 누락 |
| 같은 값이 N번 반복 | 반복 안에서 "변수 설정"을 썼다 |

> **멱등**: 같은 데이터를 몇 번 보내도 `(source, kind, at)` 기준으로 정리된다.
> 단축어가 두 번 울려도, 백필을 다시 돌려도 중복되지 않는다. 마음 놓고 재시도해도 된다.
>
> ⚠️ **다만 재시도는 자동이 아니다.** 서버가 꺼져 있거나 네트워크가 끊기면 **그날
> 데이터는 유실된다.** 아이폰은 "실행됨" 알림까지 띄우는데 연결 실패는 조용히
> 지나간다. 복구는 `export.xml` 백필을 다시 돌리는 것뿐이다.

## 3. 맥 수집기 — 브라우저 기록

```bash
python collectors/chrome_history.py --hours 24 --dry-run   # 뭐가 갈지 먼저 본다
JARVIS_INGEST_TOKEN=... python collectors/chrome_history.py --hours 24
```

한 시간마다 자동으로:

```bash
cp collectors/launchd/ai.jarvis.chrome.plist ~/Library/LaunchAgents/
# 안의 경로·토큰을 고친 뒤
launchctl load ~/Library/LaunchAgents/ai.jarvis.chrome.plist
tail -f /tmp/jarvis-chrome.log
```

> 프로필을 자동 탐색한다. 크롬은 계정을 추가할 때마다 `Profile N` 을 만들고
> `Default` 는 몇 달 전에 멈춰 있는 일이 흔하다.

## 4. 텔레그램 — 마지막이지만 제일 중요하다

**이걸 안 붙이면 자비스가 판단을 해도 아무에게도 닿지 않는다.**

> 사고 이력: 2026-08-29 수집이 멈췄고 자비스는 9월 12일까지 매일 경고했다.
> 텔레그램이 없어서 24번의 경고가 전부 콘솔에만 남았고, 한 달을 몰랐다.

1. 텔레그램에서 `@BotFather` → `/newbot` → 토큰 받기
2. **만든 봇에게 아무 말이나 먼저 보낸다.** 텔레그램은 사용자가 먼저 말을
   걸지 않은 상대에게 봇이 메시지를 못 보낸다. 이걸 빼면 다음 단계가 빈 값이다.
3. `chat_id` 알아내기:
   ```bash
   curl -s "https://api.telegram.org/bot<토큰>/getUpdates" | python3 -m json.tool | grep -A3 '"chat"'
   ```
4. `.env` 에 두 값을 넣고 `sudo systemctl restart jarvis`
5. 이 경고가 **사라지면** 성공: `텔레그램 설정이 없다 — 콘솔로 출력한다`

## 5. 회고 돌려보기

흔적이 쌓이면 손으로 한 번 돌린다. 아직 자동으로 안 돈다.

```bash
.venv/bin/python -m app.reflect --days 7
.venv/bin/python -m app.reflect --show     # 지금 믿음만 본다
```

## 막혔을 때

| 증상 | 볼 곳 |
|------|-------|
| 폰에서 아무것도 안 옴 | 단축어 "실행 전에 묻기" 꺼졌나 / Tailscale 켜졌나 |
| `404 Not Found` | 서비스가 옛 코드를 물고 있다 → `systemctl restart jarvis` |
| `401` | `Authorization: Bearer <토큰>` 헤더 확인 |
| 자비스가 아무 말도 안 함 | 텔레그램 설정 / `journalctl -u jarvis | grep 주기` |
| 판단이 계속 실패 | vLLM이 로딩 중일 수 있다. 27B는 10분 걸린다 |
| 값이 이상함 | 해당 섹터의 `_GUIDE.md` 금지사항부터 읽는다 |
