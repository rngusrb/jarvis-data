# SPRINT 2026-11-06 — 4단계 다섯째: 일정표 먼저 읽기, 어떤 파일이든 읽는 리더

## 목표

웹 검색을 켠 첫날 실제 대화에서 둘이 드러났다. "정처기 이번년도 실기 다 끝났나?"는 맞게 답했는데, "접수기간을
봐야지"에는 "공지 본문엔 없고 첨부 PDF 에 있을 텐데 못 열었어"로 끝났다. 공식 일정표 페이지가 검색 결과에 있었는데
사이트 첫 화면 둘과 공지 글을 읽었고, 검색어를 바꿔 다시 찾지도 않았다. 사용자 요청(2026-11-06): "어떤 파일이든
열어 볼 수 있는 리더도 있으면 하는데". 두 태스크를 한 리뷰에 넣었다.

### JAR-035: 파일 읽기와 첨부
- **완료 기준 달성**: ✅ (리뷰 1차 REVISE → 2차 REVISE → 사용자 결정으로 3차 PASS → 그 Low 도 고침)

  - `brain/files.py` — 종류는 첫 바이트부터(큐넷은 PDF 를 octet-stream 으로 준다), PDF(앞 30쪽, 빈 암호는 연다)·
    HWP(OLE, 문단 레코드)·HWPX·DOCX·XLSX·PPTX·글. 글만 뽑고 실행하지 않는다
  - **분석은 별도 프로세스에서**(`extract`) — 메모리 1GB·CPU 30초, 시간을 넘기면 끝냄, 비밀값 없는 환경, `-I`,
    동시에 둘. 자식에서 나오는 통로도 상한(`_talk` — 글 1MB, 오류 출력은 끝 4KB), 자식은 로깅·경고를 끈다
  - 그 안에서도 푸는 양을 센다 — HWP 는 조금씩, zip 은 stored·deflate 만 조각으로 누적, OLE 는 크기 먼저(작은
    스트림 칸까지)와 구조 검사(`DEFECT_INCORRECT`)
  - `web.PageReader` — 파일 15MB(글 페이지·json·csv 는 2MB), 40초. 그림·영상은 받기 전에 거절
  - 첨부 링크(`links_of`) — 같은 사이트만, 풀어 쓴 주소 500자·인코딩 1,000자·10개, 확장자 없는 게시판 첨부는
    링크 글로, 큐넷 첨부 버튼은 GET 주소로. 첨부는 검색 결과로 읽은 페이지에서만(한 단계). 요청은 모델이 쓴
    글자가 아니라 받은 그대로의 주소로(`tools._State.seen` — {정규화: 원래})
  - 의존성 `pypdf[crypto]>=6.21`(실측 — 6.20 은 조작한 PDF 에 150초+), `olefile`. 서버 `jarvis` 유닛에
    `MemoryMax=3G`(사용자 결정·적용, SETUP)
- **재현 명령어**: `python -m pytest tests/unit/test_files.py tests/unit/test_web.py tests/unit/test_tools.py`
