    손잡이로 길이를 먼저 보고 상한 안일 때만 받는다(`_bounded`, 본문 body 2MB·누를 것·제목). 페이지 스크립트는
    try/catch 와 프로토타입 없는 결과, 알림창은 구독 안 함, 잡히지 않은 오류는 init script 로 막음

  - `brain/badsites.py` — 문제를 일으킨 사이트 30일 기억(사용자 요청 "그 페이지는 그냥 거르게 해"). 안전장치에

## 발견된 사고와 추가된 규칙 (`src/brain/_GUIDE.md`)

- 크롬의 보안 격리를 끄고 돌지 않는다 · 브라우저가 문을 거치지 않고 나가게 두지 않는다(WebRTC 130 패킷)
- 공개 주소라고 다 밖이라고 보지 않는다 — 이 집의 공인 주소(헤어핀으로 공유기 관리 화면)
- 손이 누르지 않은 내려받기·새 창을 받지 않는다(창 60개로 손의 화면을 넘김)
- 페이지가 준 값을 크기를 보기 전에 넘겨받지 않는다(2·3차 — 1.3~1.6GB)
- 페이지가 스스로 내는 것을 받아 오지 않는다(4차 — 알림창·오류·이름표·오류 글, 1.2~1.6GB)
- 격리 허용 프로필을 사용자가 고칠 수 있는 경로에 붙이지 않는다 · 다루는 손에게 사용자의 기록을 주지 않는다
- (시험) PR CI 에서만 브라우저 시험 32개가 실패 — 파일 리더 시험이 자식용 상한(1GB·30초)을 시험 프로세스에 걸어
  크롬·드라이버가 물려받고 죽었다(맥은 메모리 상한이 안 먹음). `tests/conftest.py` 가 상한을 바꾼 시험을 실패시킨다
- (시험) CI 에서는 CDP 로 탭을 죽여도 "죽었다" 알림이 안 오고 탭이 멈춘다(두 번 연속). 사용자 결정: 그 시험만 CI 에서
  건너뛴다(맥·서버에서는 돈다). 알림이 늦게 와도 죽었다고 말하게 고쳤고, 그것은 가짜 프레임 시험이 지킨다
