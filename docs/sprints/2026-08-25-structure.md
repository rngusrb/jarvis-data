# 2026-08-25 — 플랫폼/섹터 구조 확립 + 바이브 키트 이식

## 배경

수면 하나로 돌아가던 파이프라인에 이동관리·쇼핑·스케줄 섹터를 얹을 예정이었다.
당시 구조는 **레이어 우선**(`parsers/`, `triggers/`, `storage/`)이라 섹터를 하나 늘리려면
네 폴더를 헤집어야 했고, 각 폴더에 무관한 도메인 파일이 쌓이는 구조였다.

## 한 것

### 1. 지표 카드 (PR #6)

`sleep_hours` 하나를 네 파일이 조금씩 알고 있었다 — 파서는 이름, 수신구는 접는 법,
배선은 수집 경로와 라벨, 트리거는 끊김 기준. 휴식기 심박 전환 때 실제로 어긋났다.

`Metric` 카드가 넷을 모은다. 섹터가 소유하고 플랫폼은 읽기만 한다.
수신구에서 `SLEEP_KIND`·`SUMMED_KINDS`·`AVERAGED_KINDS` 가 사라졌다.

### 2. `app/` 분해 (PR #7)

537줄에 네 가지 일. 루프와 수신구를 `src/runtime/` 으로 내렸다. `app/` 은 82줄.

### 3. health 섹터화 (PR #8)

`parsers/health.py` 가 애플 XML 파싱과 하루치 접는 산수를 함께 갖고 있었다.
접는 계산 → `src/core/folding.py` (도메인 지식 0, `source` 조차 인자),
애플 XML → `src/sectors/health/parser.py`. `src/parsers/` 폴더는 사라졌다.

덤으로 `parse_export` 가 접힌 `heart_rate_avg` 대신 `resting_heart_rate` 를 뽑게 되어,
1건뿐이던 지표에 **102일치 baseline** 이 생겼다.

### 4. 바이브 키트 이식

`harness all` 이 완료의 단일 정의가 됐다. CI 와 갈라지지 않도록 ruff·mypy 를 묶었다.
폴더 8개에 `_GUIDE.md`, 금지사항은 전부 **실제로 난 사고**에서 가져왔다.

## 결정과 근거

**플랫폼/섹터 경계를 지금 세운 이유**: 섹터가 하나뿐이라 추상화가 이르다고 판단했으나,
사용자가 로드맵(이동·쇼핑·스케줄)을 명시했고 나중에 옮기는 비용이 더 크다.
다만 **섹터를 데이터로 선언해 LLM이 생성하게 하는 것**은 여전히 보류 — 손으로 2~3개를
만들어봐야 공통점이 드러난다.

**워치 우선 + 빈 구간 채우기**: 걸음수 기기 중복에서 "워치만" 은 배터리가 죽은 오후를
통째로 버린다. 건강 앱과 같은 방식(시간 구간마다 소스 하나)을 택했다.
