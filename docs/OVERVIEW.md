# OVERVIEW — 자비스는 무엇이고 왜 이렇게 생겼나

> 이 문서는 **왜**를 다룬다. 어디를 고치는지는 [DEV_GUIDE.md](../DEV_GUIDE.md),
> 어떻게 세우는지는 [SETUP.md](SETUP.md) 에 있다.
>
> 코드만 읽어도 무엇을 하는지는 알 수 있다. 여기 적는 건 **왜 그러지 않았는지** —
> 되돌리면 안 되는 결정과 그 근거다.

---

## 한 문단

애플 생태계(수면·심박·위치)와 브라우저 기록을 자동으로 모아, **그 사람의 평소와
어긋나는 지점**을 감지하고 로컬 LLM이 판단해 **먼저 말을 거는** 에이전트다.
데이터가 사설망 밖으로 나가지 않는다 — 그게 기능이 아니라 아키텍처 제약이었다.

---

## 1. 무엇을 풀려는가

**기존 헬스 앱은 묻지 않으면 답하지 않는다.** 데이터는 쌓이는데 사용자가 들여다볼
때만 의미가 생기고, 정작 알아야 할 순간에는 조용하다.

**반대로 알림을 늘리면 스팸이 되어 꺼진다.** 이 제품군이 죽는 대표적 방식이다.

그래서 목표를 이렇게 잡았다 — **말할 가치가 있을 때만 먼저 말한다.**

두 문장이 전부인데, 이 둘이 서로 당기는 힘이 이 레포의 거의 모든 설계 결정을
설명한다. 아래 "안 하기로 한 것"들은 대개 스팸 쪽으로 기울지 않으려는 장치다.

---

## 2. 되돌리면 안 되는 결정 일곱 개

### ① 이상 감지는 절대 기준이 아니라 개인 baseline 대비 편차

`수면 7시간 미만이면 알림`은 만들기 쉽고 **쓸모가 없다.** 이 사용자의 4개월치에
그 기준을 대면 83일 중 **73일(88%)** 에 울린다. baseline 기준으로는 11회다.

```
절대 기준 (7시간)   88% 발화  →  꺼진다
baseline 대비       13% 발화  →  들린다
```

**예외가 하나 있다** — `ChronicShortSleepTrigger`. baseline 방식에는 사각지대가
있는데, **평소가 이미 망가지면 편차가 안 보인다.** 실제로 2.77시간을 잔 날 최근
평균이 3.91시간이라 차이 1.14시간으로 문턱(1.5)에 못 미쳐 자비스는 침묵했다.

그래서 여기서만 절대 기준을 쓰되 **하루가 아니라 추세에** 건다. 하루에 걸면
만성인 사람에게 매일 울려서 정확히 저 88%가 된다. 평균에 걸면 상태가 실제로
바뀔 때까지 조용하고, 쿨다운 7일이 나머지를 막는다.

### ② 싼 게이트가 비싼 LLM 앞에 있다

```
트리거 감지  →  게이트(숫자 비교)  →  LLM  →  발송
                    ↑ 여기서 대부분 걸러진다
```

순서를 뒤집으면 30분마다 3090 두 장을 태워놓고 결국 "말할 필요 없음" 판정을 받는다.
게이트는 심각도와 쿨다운만 보므로 **공짜이고, 결정적이라 "왜 조용했는지"를 나중에
그대로 재현할 수 있다.**

### ③ 플랫폼은 섹터를 모른다 — 방향은 하나뿐

```
섹터 (health, commute, interest …)   계속 늘어난다
        ↓ 위를 쓴다
플랫폼 (core, storage, brain, runtime, triggers, channels)
        ↑
app/main.py — 섹터를 아는 유일한 파일
```

판별 규칙은 한 문장이다. **"쇼핑 섹터를 추가할 때 이 파일을 열어야 하나?"**
열어야 하면 섹터, 아니면 플랫폼.

이건 취향이 아니라 **테스트가 집행한다** (`tests/invariants/test_boundaries.py`).
한 방향 규칙을 문장으로만 두면 석 달 뒤에 누군가(작성자 포함) 무심코 어긴다.

> 왜 이렇게까지 하나: 목표가 섹터를 계속 늘리는 것이다(이동관리·쇼핑·스케줄, 그리고
> 나중에는 LLM이 스스로 만드는 것). 섹터를 늘릴 때마다 플랫폼도 고쳐야 하면
> 갈라놓은 의미가 없다.

### ④ 같은 계산은 한 곳에만

수면은 단축어로도 오고 `export.xml` 백필로도 온다. **두 경로가 다른 코드를 지나가면
같은 밤이 다른 값이 된다.**

```
백필 경로:   export.xml → merge_spans() → 8.0    ← 서버가 계산
단축어 경로: 단축어가 계산해서 보냄     → 10.0   ← 폰이 계산
```

이런 버그는 **원인이 데이터가 아니라 코드 위치**라 추적이 지독히 어렵다. 그래서
폰은 원본 구간을 그대로 보내고 접기는 전부 서버가 한다. 단축어는 배달만 한다.

> 부수 효과가 하나 더 있다. 단축어는 고치려면 아이폰을 열어야 하고, git에도 없고,
> 뭘 바꿨는지 기록도 안 남는다. **어려운 일은 고칠 수 있는 쪽에서 한다.**

### ⑤ 숫자와 텍스트는 다른 길로 간다

```
관측치 (Observation)   수면 4.5시간, 심박 62       접힌다(평균·합계)   트리거가 즉시 반응
흔적   (Trace)         "전세자금대출 금리" 검색     안 접힌다           회고가 주기적으로 훑음
```

*"전세자금대출 금리"* 를 일곱 개 모아 평균 낼 수는 없다. `Observation.value` 는
`float` 이라 애초에 들어가지도 않고, `meta` 에 쑤셔넣으면 집계도 조회도 의미를 잃는다.

**재료가 다르면 처리 경로도 달라야 한다.** 그래서 루프가 둘이다.

| | 재료 | 주기 | 하는 일 |
|---|---|---|---|
| **반응 루프** | 숫자 | 30분 + 수집 직후 | "어젯밤 2.7시간" → 즉시 판단 |
| **회고 루프** | 텍스트 | 주 단위 (지금은 수동) | "요즘 이사를 알아보네" → 믿음 갱신 |

"전세대출을 검색했다"고 알림을 보내는 건 이상하다. 흔적 하나로는 아무 말도 할 수
없고, 서른 개가 모여야 의미가 된다.

### ⑥ 믿음에는 근거·확신·수명이 필수다

`Belief` 는 자비스가 **추론해낸** 것이다. 관측치·흔적은 일어난 사실이고, 믿음은
그것을 보고 지어낸 해석이다. 틀릴 수 있다는 뜻이다.

```python
Belief(
    kind="관심사:주거",                    # ← LLM이 만든다
    value="전세자금대출을 알아보는 중",
    confidence=0.7,
    evidence=("전세자금대출 금리", ...),   # ← 없으면 생성 자체가 거부된다
)
```

`evidence` 를 `__post_init__` 에서 막는다. 저장 직전에 막으면 이미 프롬프트에 들어간
뒤라서다. **근거를 실제보다 세게 말하는 게 이 방식의 주된 실패 모양이다** — 실제로
모델이 7일 평균 두 개를 비교해놓고 "상관관계가 뚜렷하게 나타난다"고 쓴 적이 있다.

그리고 **수명이 있다.**

```
새 근거 ──→ [후보] ──근거 또 나옴──→ [확정] ──14일 조용──→ [시듦] ──30일──→ [망각]
```

늘리는 쪽만 있으면 이 구조는 죽는다. LLM은 새 `kind` 를 아주 잘 만든다 — 너무
잘해서 문제고, 2주면 `관심사:주거 / 관심사: 주거 / housing_interest / 이사 / 전세`
가 공존한다. 그래서 **만들기 전에 기존 목록 전부를 보여주고**, 안 쓰이는 건 지운다.

관심사는 원래 사라진다. 이사를 가버리면 전세 검색이 멈춘다.

### ⑦ 로컬 LLM은 비용 절약이 아니라 전제다

모으려는 것 대부분이 **클라우드 AI에는 보낼 수 없는 것들**이다. 검색 기록, 메시지,
결제 내역, 위치. OpenAI에 이걸 던지는 건 말이 안 된다.

**자비스는 보낼 수 있다.** 3090 두 장이 집에 있고 vLLM이 거기서 돌고, 데이터가
Tailscale 밖으로 한 번도 안 나간다. 이게 클라우드 기반 경쟁자가 구조적으로 못 하는
부분이고, 그래서 `Reasoner` 프로토콜의 기본 구현이 로컬인 것이다.

## 3. 데이터가 흐르는 길

```
  아이폰 단축어            맥 수집기              export.xml
  (수면·심박·위치)         (크롬 기록)            (일회성 백필)
        │                      │                      │
        └──── Tailscale ───────┴──────────────────────┘
                              ↓
                      runtime/ingest          네 개의 문
                       /ingest        이미 계산된 값
                       /ingest/spans  구간 원본      ← 수면
                       /ingest/samples 표본 원본     ← 위치·심박
                       /ingest/traces  텍스트        ← 브라우저
                              ↓
                      core/folding            겹침 병합 · 기기 중복 제거 · 하루치 집계
                              ↓
                      storage/sqlite          (source, kind, at) 멱등 쓰기
                              │
            ┌─────────────────┴─────────────────┐
            ↓                                   ↓
    runtime/loop (30분)                 brain/reflect (주 단위)
      triggers → 편차 감지                 흔적을 훑어 믿음 갱신
      brain/gate → 싼 필터                 오래된 믿음 망각
      brain/agent → vLLM 판단
      channels → 텔레그램
```

**수신구가 네 개인 이유**는 재료가 네 가지이기 때문이다. 수면은 조각 수가 품질
신호라 원본 구간이 필요하고, 위치는 하루 여러 점이라 접으면 안 되고, 브라우저
기록은 숫자가 아니다.

## 4. 이 프로젝트가 실제로 배운 것

**규칙은 사고에서만 생긴다.** 각 폴더의 `_GUIDE.md` 금지사항에는 반드시 사고 이력이
붙어 있다 — 이유 없는 규칙은 다음 사람이 지운다.

아래는 그중 되풀이되기 쉬운 것들이다.

### 플랫폼이 자기 앱과 같은 값을 준다고 믿지 마라

```
HealthKit 그룹화 = 일   8/18 → 15,480   (워치 7,980 + 아이폰 7,500 을 그냥 더함)
애플 건강 앱            8/18 →  9,288   (시간 구간마다 소스 하나)
```

같은 애플 기능인데 값이 달랐다. 건강 앱이 쓰는 통계 질의는 **구간마다 소스를 하나만
고르는데** 단축어의 그룹화는 원본 표본을 단순 합산할 뿐이다. 같은 방식을 직접
구현했다(구간 단위 겹침 판정, 워치 우선, 겹침 비례 배분). 4개월 평균 **15,856 →
7,928보.**

원본 심박도 같은 함정이었다. 그룹화가 평균이 아니라 **합계**로 묶어서 심박이
**13,732** 로 왔다.

### 표본 수가 폭탄이다

| | 하루 표본 |
|---|---|
| 걸음수 (평상시) | 30~80개 |
| 걸음수 (운동한 날) | **1,112개** ← 단축어가 반복을 못 끝내고 멈춘다 |
| 원본 심박 | 361개 (최대 1,157개) |
| 휴식기 심박 | **1개** |

며칠은 통과하다가 운동한 날 멈춘다. **표본 수가 안정적인지 먼저 확인하고 수집
방식을 정한다.** 걸음수는 접었고, 심박은 워치가 이미 계산해둔 값으로 갈아탔다.

### 부분 데이터가 완전한 데이터를 덮어쓴다

어제 8.00시간으로 저장된 밤이 오늘 1.00시간이 되어 있었다. 수집 자동화가 "최근
1일" 롤링 창으로 보내는데, 평소보다 일찍 깬 날은 전날 밤이 **잘린 채로** 재전송된다.
멱등 쓰기가 짧은 값으로 덮어썼다.

```sql
ON CONFLICT(source, kind, at) DO UPDATE SET value = excluded.value
WHERE excluded.value > observations.value
```

한 문장이라 동시 요청에도 경합이 없다. 단, **백필은 여전히 REPLACE** 다 — 백필의
값이 더 정확하므로 거기서 KEEP_LARGER 를 쓰면 잘린 값이 영구히 남는다.

### 로케일이 필터를 통째로 무력화한다

수면 단계를 `"Asleep" 이 포함된 것만 통과` 로 걸렀다. 폰은 한국어로 `"수면 시간"`
을 보낸다. **전부 걸러져서 `written: 0`.**

테스트를 뒤집었다 — 수면인 것을 **admit** 하지 않고 수면이 아닌 것을 **exclude**
한다. 수면을 가리키는 말은 출처·언어마다 다르지만, 깨어 있음을 가리키는 말은 적다.

### `None` 은 문자열 `"None"` 이 되어 발송된다

reasoning parser 를 쓰는 서버는 생각 도중에 잘리면 `content: null` 을 돌려준다.
`str(None)` 이 `"None"` 이 되어 사용자에게 갔다. `isinstance(content, str) and
content.strip()` 로 막고, `finish_reason` 을 로그에 남긴다.

### 출처와 전송 경로는 다르다

`source="shortcuts"` 로 두었다. 저장소 키가 `(source, kind, at)` 이라 **같은 밤이
단축어와 백필에서 각각 한 줄씩 남는다.** 그러면 baseline이 그 밤을 두 번 센다.

우편함에 들어온 편지에 "우체부가 가져옴"이라고 발신인을 적은 셈이다. `apple_health`
로 고쳤다.

### 예외 하나가 루프 전체를 멎게 한다

vLLM이 로딩되는 10분 동안 아침 신호 4건이 사라졌다. 판단이 예외로 터졌고 그 예외가
`_cycle` 밖으로 새면서 **뒤에 선 트리거들은 검사조차 되지 않았다.** 발송 실패는
이미 보호돼 있었는데 판단 실패만 아니었다.

### 감시견이 가장 필요할 때 침묵했다

2026-08-29 수집이 멈췄다. 자비스는 9월 12일까지 매일 경고했고 **9월 13일부터
조용했다.** `StaleDataTrigger` 의 창이 14일이라 8월 29일 기록이 밀려났고, 빈 창은
"아직 시작 안 함"으로 판정된다.

**좁은 창에서는 "한 번도 없음"과 "오래전에 끊김"이 구별되지 않는다.** 중단이
심해질수록 감시견이 조용해졌고, 그대로 한 달을 보냈다.

감시견에게는 창이 없어야 한다. baseline을 계산하는 트리거는 최근 구간만 보면 되지만
이쪽이 알아야 할 건 "마지막 기록이 언제냐" 하나다.

### 경고는 닿아야 경고다

같은 한 달 동안 자비스는 **24번 경고했다.** 텔레그램이 안 붙어 있어서 전부
`journalctl` 에만 남았다. 판단이 정확해도 채널이 없으면 아무 일도 일어나지 않는다.

### 레포 밖 문서는 반드시 낡는다

단축어 설정을 잘 정리한 가이드가 있었는데 레포 밖(아티팩트)에 있었다. 한 달 뒤
열어보니 서버 주소가 옛 맥이고, 이미 접은 지표가 살아 있었다. **버전 관리 안 되는
문서는 코드와 같이 낡지 않는다** — 같이 낡으면 티가 나는데, 따로 낡으면 안 난다.

## 5. 지금 무엇이 돌고 있나

솔직하게 적는다. 동료가 "다 돈다"고 믿고 시작하면 첫날에 헷갈린다.

| | 상태 |
|---|---|
| 자비스 서버 (systemd) | ✅ 상주. 30분 주기 |
| vLLM (Qwen3.8-27B-FP8, TP=2) | ✅ `unless-stopped` |
| 플랫폼/섹터 구조 + 불변식 테스트 | ✅ |
| 숫자 층 (관측치·트리거·게이트·판단) | ✅ |
| 텍스트 층 (흔적·믿음·회고) | ✅ 코드는 완성. 회고는 **수동 실행** |
| 크롬 수집기 | ✅ 코드·launchd 설정 완성. **설치는 안 됨** |
| **폰 수집** | ⚠️ **2026-08-29부터 멈춤.** 원인 미확인 (서버는 정상, 폰 쪽) |
| **텔레그램** | ❌ 미연결. 자비스 발화가 로그에만 남는다 |
| 믿음 → 발화 연결 | ❌ 자비스가 "채용 준비 중"을 알지만 그걸로 말을 걸지 않는다 |

**가장 급한 것은 텔레그램이다.** 이게 없으면 다음에 멈출 때 또 한 달 뒤에 안다.

## 6. 어디까지 확인된 것들

말로만 있는 게 아니라 실제 데이터로 나온 결과들이다.

**통근 경로가 통째로 잡혔다.** 위치에 `trigger` 라벨을 붙인 뒤:

```
07:29  집         leave_home
        ↓ 235m,  4.3km/h   도보 3분
07:32  정류장     wallet      ← 버스 탐
        ↓ 1084m, 11.7km/h  버스 6분
07:39  역         wallet      ← 버스 내림
07:40  역         wallet      ← 지하철 탐
        ↓ 12.2km, 20.8km/h  지하철 35분
08:15  도착지     wallet      ← 지하철 내림
```

이틀 연속 오차 2분 이내였고, **아침에 사라진 지점에서 저녁에 2m 오차로 다시
나타났다.** 그 좌표가 타는 역이다. 갈 때 34분 / 올 때 36분으로 대칭이라 같은 노선
왕복인 것도 확인됐다.

`wallet` 태그가 갈아타는 지점마다 찍힌 건 티머니가 Wallet에 있어서다 — 지갑
자동화의 카테고리에 "교통"을 체크해둔 덕이다.

**회고가 브라우저 기록에서 관심사를 뽑아냈다.** 220건(최근 7일 120건)에서:

```
[관심사:채용준비]        확신 0.9   근거: KT 2026 대졸신입 / LG전자 하반기 / 토스 채용
[관심사:AI프로젝트개발]  확신 0.9   근거: RAG 시스템 구축 / 임베딩·Qdrant / 랭그래프
[관심사:데이터활용]      확신 0.8   근거: 농수산식품유통공사 / 공공데이터 오픈 API
기각 1건 — 근거가 1개뿐
```

**기각이 작동한 게 제일 중요하다.** 근거 없이는 믿음이 만들어지지 않는다.

## 7. 어디로 가는가

장기 목표는 **섹터를 LLM이 스스로 늘리고 줄이는 것**이다. 지금은 두 계단 앞이다.

```
1단계  사람이 섹터를 만든다                        ← 지금
2단계  LLM이 데이터 종류(믿음의 kind)를 만든다      ← 지금. 정해진 그릇 안에서
3단계  LLM이 "이런 기능이 있으면 좋겠다"를 제안한다  ← 실험까지 함
4단계  LLM이 섹터·트리거를 직접 만든다              ← 아직
```

3단계는 실제로 돌려봤다. 모델에게 데이터 요약과 기존 기능 목록을 주고 "새로 있으면
좋을 기능"을 물었더니 **수면-심박 연동**을 짚었다(수면이 줄면서 휴식기 심박이
오르는 걸 발견). 기존 트리거를 다시 제안하지 않았고, 데이터가 부족한 영역은 아예
건너뛰었다. **"기존 목록을 먼저 보여준다"가 먹힌다는 증거**이고, 그 방식을 그대로
믿음 생성에도 쓰고 있다.

단기 우선순위:

| | 왜 |
|---|---|
| **텔레그램** | 이게 없으면 나머지가 다 무의미하다 |
| 폰 수집 복구 | 한 달째 멈춰 있다 |
| 믿음 → 발화 | 알아낸 걸 쓰지 않고 있다 |
| 회고 자동화 | 품질을 몇 번 눈으로 본 뒤 주기를 정한다 |
| 캘린더 | 수면의 **왜**를 알려줄 후보. 지금 자비스는 원인을 전혀 모른다 |
